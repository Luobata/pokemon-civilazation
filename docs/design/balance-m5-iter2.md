# B3：第二轮平衡迭代方案

> 本文只设计下一轮实验，不修改 GDD、正式数值或 AI 行为。A/B 是实验数据；I1–I6 的预期均为待模拟验证的假设。轮上限保持100，保留B的城市基础HP80与城市计分×80作为共同底座，避免继续改变对照条件。

## 1. 数据与限制

输入为新基线 `m5-4-base`、方案A `m5-4-plan-a`、方案B `m5-4-plan-b`，同一100种子、300局。分析脚本 `/tmp/balance_m5_iter2_analysis.py` 直接读取三批逐局JSON；完整输出为 `/tmp/balance_m5_iter2_analysis.json` 与 `.stdout.json`。

| 指标 | 新基线 | A | B | 目标 |
|---|---:|---:|---:|---:|
| 征服 | 47/300 = 15.67% | 85/300 = 28.33% | 95/300 = 31.67% | ≥40% |
| 平均终局 | 94.23 | 89.05 | 87.83 | 70–95 |
| 1v3平均终局 | 97.76 | 94.89 | 94.23 | 70–95 |
| 好战对扩张（好战胜） | 15/66 = 22.73% | 43/66 = 65.15% | 45/66 = 68.18% | 40–60% |
| 好战对保守（好战胜） | 25/68 = 36.76% | 50/68 = 73.53% | 50/68 = 73.53% | 40–60% |
| 保守对扩张（保守胜） | 8/66 = 12.12% | 8/66 = 12.12% | 8/66 = 12.12% | 40–60% |
| 滚雪球 | 61.57% | 69.23% | 68.53% | ≤75% |

A/B没有单项消融，所以不能把联合差值精确拆成“某一项贡献百分之几”。本轮I1–I3正是为补这个识别缺口；下面只报告可观察变化及其支持强度的结论。

## 2. 原因分析

### 2.1 好战过强：主要是开拓队经济与3兵攻城同时放行，宣战车力比不是领先信号

A相对新基线：

| 变化 | 新基线 → A | 对机制的含义 |
|---|---:|---|
| 好战后续开拓队 | 160 → 681（+521，4.26倍） | 城市门槛3→2后，生产瓶颈大幅解除 |
| 好战新建城市次数 | +329 | 生产增加确实转化为扩张，不是队列空转 |
| 终局城市均值 | 2.78 → 4.63（+1.85，+66.5%） | 城市分、人口、产出共同增强 |
| 终局人口均值 | 12.09 → 16.98（+4.89） | 经济差距继续进入计分 |
| 终局场上宝可梦均值 | 4.06 → 5.80（+1.75） | 经济提升也转化为军力 |
| 终局维护均值 | 7.85 → 11.81（+3.96） | 大军有成本，但不足以抵消城市收益 |
| 实际攻城席位 | 132 → 192（+60，+45.5%） | 3兵门槛显著扩大可攻城覆盖 |
| 首次攻城中位 | 31 → 27.5轮 | 攻城整体提前3.5轮 |
| 首次占敌城中位 | 43.5 → 40轮 | 占领同样提前3.5轮 |
| 首次达3兵中位 | 21 → 21轮 | 不是“训练更早”，而是同一军力被允许用于攻城 |
| 主动宣战席位 | 233 → 243（+10） | 车力比1250只多放行10席 |
| 首次宣战中位 | 19 → 20轮 | 宣战并未更早，不支持车力比是提前进攻的主因 |

联合结果是征服47→85局，好战对扩张胜15→43局、对保守胜25→50局。扩张型城市均值同时从4.39降至3.68，说明好战增强还通过占城直接削弱对手。

**判断**：开拓队门槛与3兵攻城是最强的两个候选原因；前者带来可量化的城市/人口/军力膨胀，后者带来可量化的攻城参与扩大。1250车力比只增加10个宣战席且中位更晚，优先级较低。精确单因素贡献不能从A联合批次识别，必须用I1–I3补测，而不能虚构比例。

B相对A将成功占城攻击段中位13→11，征服再增10局，1v3征服23→28；但好战对扩张胜率继续升3.03个百分点。城市HP80和城市计分80仍是一组联合变化，本轮不分离二者的贡献。

### 2.2 保守不是单纯“扩张慢”，而是科技、城市、征服三条路线都不成立

新基线每席均值与行为总量：

| 指标 | 保守 | 扩张 | 保守缺口 |
|---|---:|---:|---:|
| 后续开拓队总数（267/266席） | 245 | 1255 | 约1/5 |
| 终局城市 | 2.20 | 4.39 | -2.19 |
| 终局人口 | 9.87 | 15.68 | -5.81 |
| 终局科技 | 5.72 | 6.37 | -0.64 |
| 场上宝可梦 | 3.87 | 7.02 | -3.15 |
| 主动宣战 | 0 | 0 | 都不能靠主动战争开路 |
| 首次攻城 | 47/267席 | 0/266席 | 保守仅17.6%席位 |
| 首次占敌城 | 28/267席 | 0/266席 | 转化范围很小 |
| 大本营占领 | 24 | 0 | 有反攻，但不足以形成稳定路线 |
| 捕捉尝试 | 319 | 1494（扩张总量） | 补充单位/图鉴差距大 |

“科技优先”也没有形成优势：保守科技均值5.72低于扩张6.37，1v1保守对扩张平均科技差为扩张+0.91。城市×100时保守对扩张平均总分差349.88；B改为×80后平均差缩到299.58（缩小50.30），但66局胜者完全不变，且**66局全部计分、0局征服**。所以降低城市分有帮助但不够，单靠计分权重不能给保守一条征服路线。

A没有触碰保守门槛，保守反而因好战增强而城市2.20→1.76、人口9.87→7.72、科技5.72→4.95，攻城543→360。这解释了好战对保守从36.76%升到73.53%：不是保守自身变强，而是被扩张/进攻双重挤压。

**关键规则边界**：保守只在“被宣战后且己方军力≥对方2倍”时反攻，扩张又从不主动宣战。因此仅把 `conservativeStrength` 从2000降低，理论上可改善保守对好战，却无法给保守对扩张提供征服路线。保守对扩张目前只能走经济计分路线，必须先实验15→8的开拓队节奏；若仍失败，就需要用户决定是否修改§3.14行为文字。

## 3. 第二轮因子实验

共同底座均为：

```json
{
  "balance": {
    "city": { "baseHp": 80 },
    "score": { "cities": 80 }
  }
}
```

默认未写字段保持正式默认：好战开拓队城市3、攻城4兵、宣战车力比1500；保守反攻倍率2000、开拓间隔15。六个补丁已用 `parsePatch` 全部验证通过，结果在 `/tmp/balance_m5_iter2_patch_validation.json`。本轮不加入B2物种补丁，避免把性格/城市因素与物种因素再次混合。

### I1：军事放行，不放经济

假设：若A的强势主要来自3兵和车力比，I1会保留较高征服与好战胜率；若胜率明显低于A，则证明经济门槛是必要放大器。

```json
{
  "balance": { "city": { "baseHp": 80 }, "score": { "cities": 80 } },
  "ai": { "aggressiveSiegeUnits": 3, "aggressiveWarStrength": 1250 }
}
```

对比：I1 vs B，差好战开拓队城市3→2，估计经济因素的贡献；I1 vs I3，差3兵攻城。

### I2：只放经济

假设：若城市数和分数上升但攻城参与不增，经济本身不足以解释A的征服提升；若也好战过强，则3→2已经足以造成主要失衡。

```json
{
  "balance": { "city": { "baseHp": 80 }, "score": { "cities": 80 } },
  "ai": { "aggressiveSettlerCities": 2 }
}
```

对比：I2 vs B，差军事两项；I2 vs I3，只差宣战车力比1500→1250。

### I3：经济+宣战折中，恢复4兵攻城

假设：保留经济路线，但推迟低军力攻城，可把65–74%的好战胜率压回40–60%，同时保留比基线更高的征服。

```json
{
  "balance": { "city": { "baseHp": 80 }, "score": { "cities": 80 } },
  "ai": { "aggressiveSettlerCities": 2, "aggressiveWarStrength": 1250 }
}
```

对比：B vs I3只差攻城4→3，是本轮最直接的军事折中；I3也是保守因子的共同对照。

### I4：保守经济路线

假设：开拓间隔15→8能增加保守城市、人口与科技，缩小对扩张的计分差；它不改变保守对好战的反攻条件，避免直接加强抗好战。

```json
{
  "balance": { "city": { "baseHp": 80 }, "score": { "cities": 80 } },
  "ai": {
    "aggressiveSettlerCities": 2,
    "aggressiveWarStrength": 1250,
    "conservativeSettlerInterval": 8
  }
}
```

对比：I4 vs I3，只差保守开拓间隔；重点看保守对扩张、城市/科技均值，不期待对扩张产生征服。

### I5：保守反攻路线

假设：反攻倍率2000→1500能增加被宣战后的攻城与HQ占领，改善保守对好战；对扩张若无变化，将实证“没有战争触发就没有反攻路线”的规则边界。

```json
{
  "balance": { "city": { "baseHp": 80 }, "score": { "cities": 80 } },
  "ai": {
    "aggressiveSettlerCities": 2,
    "aggressiveWarStrength": 1250,
    "conservativeStrength": 1500
  }
}
```

对比：I5 vs I3，只差保守反攻倍率；分别报告对好战和对扩张，不能用整体胜率掩盖后者可能不变。

### I6：保守经济+反攻组合

假设：经济路线提高计分竞争力，反攻路线增加征服，二者合用最可能同时改善三组配对和总征服率；若出现过强，再按I4/I5的单因素结果回退。

```json
{
  "balance": { "city": { "baseHp": 80 }, "score": { "cities": 80 } },
  "ai": {
    "aggressiveSettlerCities": 2,
    "aggressiveWarStrength": 1250,
    "conservativeSettlerInterval": 8,
    "conservativeStrength": 1500
  }
}
```

对比：I6-I4测反攻增量，I6-I5测经济增量；交互项用 `I6 - I4 - I5 + I3` 估计，不把组合提升全部归因于某一字段。

## 4. 运行与胜者选择

1. 六个补丁都跑与M5-4相同100种子（300局），manifest保留patch和SHA；同patch双跑确认确定性。逐批报告0 defect、aborted、fog拒绝和提前终局。
2. 先读I1–I3决定好战折中，再读I4–I6判断保守路线；不要只挑整体胜率最好的一局。
3. 每批必报征服、平均终局、1v3终局、三组配对、先手、无属性优势击坠、滚雪球、捕捉、维护/城市/科技、首次3/4兵与攻城、占城攻击段和HQ清场转化。
4. 若候选接近阈值，按D18追加相关新种子；最终发布候选仍需独立新样本，不用同100种子反复调参后直接宣称验收。

**选择顺序**：

1. 硬排除：defect非0、aborted>5%，或把先手>55%、滚雪球>75%、捕捉离开3–10、无属性优势击坠≤25%、平均/1v3轮数越界的候选排除。
2. 全部原目标达标者优先；其中选三组配对离40–60最大距离最小者，再选滚雪球更低者，避免换一种极端。
3. 若没有全达标：先按“三组配对中双方均落40–60%的组数”降序，再按征服率降序，再按三组配对到40–60区间的最大距离升序，最后按滚雪球升序。不能只按征服最高选胜者。
4. 若保守对扩张仍明显失衡而好战已回40–60%，保留好战设置、只迭代保守因素；不得重新加强好战来掩盖保守问题。
5. 没有候选满足要求时输出“下一轮实验胜者”而非“平衡通过”，按上述顺序选择最值得追加验证的一组，并保留原始数据。

## 5. 超出D40数值授权、需用户决定的事项

以下不在I1–I6中实施；只有数据表明确有数值字段仍无法提供路线时才提交用户：

1. **保守有限主动宣战**：当前§3.14写“从不主动宣战”。可提议改为“已观察军力≥对方2倍且接壤时可主动宣战”，需要新增保守主动宣战/接壤门槛及相应AI实现。它能让保守对扩张也有征服路线，但会明显改变性格，必须用户拍板。
2. **保守捕捉范围**：现有patch只有 `aggressiveCaptureRadius`，没有保守对应字段。若要把“仅捕捉己方领地内野生”改为“己方领地或邻近战区≤N格”，需要新增 `conservativeCaptureRadius` 并修改§3.14该句及AI资格判断。它只能补充军力，不能代替战争路线。
3. **新的计分结构**：若保守科技路线仍弱，是否给科技型性格专门计分优势属于玩法方向，不能用现有通用数值字段暗中实现；先由用户决定是否要这种性格专属规则。
4. **B2物种补丁**：本轮不采用。若I1–I6证明兵种交换而非AI/城市是主因，再按B2的单物种消融流程另行提交，避免超出当前因子实验。

城市HP80、城市计分×80以及I1–I6使用的AI数值门槛都属于D40已授权的迭代范围，不需要新增玩法授权。
