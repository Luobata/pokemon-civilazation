# 2.5D 地图与界面改造（ui-25d）

2026-11-19 · 用户反馈：“可以对 UI 做重点改造，目前看 UI 比较简单，原作应该有一些 2.5D 的感觉。”

现在的地图是正上方俯视的平面六角格：地块是平铺的生物群系贴图，山、丘陵是贴在格子里的小图标，单位是站在圆盘上的平面精灵。目标是加上“纵深”：像掌机捕虫类 RPG 的大地图那样“略微从上往下看”的层次感，以及文明系列倾斜地图那种“地块有高度、有崖壁、有影子、东西竖立在地面上”的感觉。

**原创约束**：只借用 2.5D 的通用手法（斜投影 / 压扁、地块侧面挤出、台阶式高度、投影、竖立的广告牌精灵、按深度排序），不复制任何已有游戏的地块、精灵、界面框或布局。所有新美术都是本项目用代码逐像素画出的硬边像素画（和 `public/buildings/README.md`、`map-icons.ts`、`ui-icons.ts` 一致）；宝可梦物种精灵继续用 `public/sprites/` 里现有的图。

原型已经实现在 `?render=25d`（或 菜单 → 地图视角 → 2.5D 立体）后面，默认仍是平面。截图见 `docs/design/ui-25d/`。

---

## 1. 投影：两个方案

| | A. 压扁六角格 + 挤出侧面（推荐） | B. 真等距（isometric，菱形网格） |
| --- | --- | --- |
| 做法 | 世界坐标 y 乘 0.75（相机俯角约 41°），六角格画成扁六边形；每格按高度上移，前面两条边（西南、东南）向下挤出崖壁 | 把地图旋转 45°/压扁 0.5，格子变成菱形或扁平六边形，左右两面都可见 |
| 与规则的关系 | 六角格邻接、距离、东西环绕完全不变；`hexToWorld` 一处乘系数，其他所有世界坐标（动画、相机、弹道）自动跟着变 | 六角格要么改成菱形视觉（与规则的 6 邻接对不上），要么斜着排的六角格，环绕接缝变成斜线 |
| 东西环绕 | 接缝仍是竖直线，`copyShifts` 不用改 | 接缝是斜线，副本要沿对角线平移，缓存和拾取都要重写 |
| 拾取 | 平面反算 + 前两排候选，按“从前往后”测试柱体（§8），纯函数 | 需要整套等距反算和菱形/六边形混合判定 |
| 文字与图标 | 横向不变形，城市横幅、产出图标、数字照旧可读 | 横向也被斜切，文字只能浮在上层 |
| 工作量 | 小：一个新后端模块 + `camera.ts` 一个系数 | 大：相机、拾取、环绕、所有叠加层都要改 |

**推荐 A。** 压扁 0.75 让地图有明显的“斜着看下去”的感觉，又保留六角格的可读性和全部规则几何；南北方向的距离感由高度和侧面来补。俯角不随缩放变化（缩放时变的话，拾取和缓存键都会抖动），以后若要“拉近时更倾斜”，可以在 0.7–0.8 之间按缩放分三档离散切换。

## 2. 高度模型

高度以世界像素计（`HEX_RADIUS = 22` 的尺度，随缩放），定义在 `src/browser/render/projection.ts` 的 `ELEVATION`：

| 地形 | 高度 | 说明 |
| --- | --- | --- |
| 未探索 | −16 | 最低，探索过的土地像从黑暗中升起的模型台（不画侧面） |
| 海洋 / 远洋 / 湖泊 | −8 | 水面统一一层；远洋只换更深的水色，不做台阶（水面不该有“水崖”） |
| 草原 / 森林 / 沙漠 | 0 | 基准面（海岸一圈） |
| 内陆台地（第二轮） | +3.5 / +7 | 离已知水面 2–3 格升一级、4 格以上再升一级；叠加在所有陆地上 |
| 雪原 | +2 | 微微隆起的雪层 |
| 山地 / 火山 | +8 | 生物群系本身就高 |
| 丘陵（v24 特征） | +6 | 叠加在生物群系上 |
| 高峰（v24 特征） | +14 | 叠加；配一座竖立的岩峰 |

- 高度只属于表现层：从场景（PlayerView 已知的生物群系和特征）算出来，不进存档，不影响规则。v≤23 的地图没有丘陵 / 高峰特征，只有生物群系的高低。
- 遮挡：比后面一格高 8.25 以上的格子会挡住后面那格的中心（行距 24.75 − 顶面半高 16.5，俯角 0.75），例如高峰挡住它正北的格子。常见的台阶（水 → 陆、陆 → 丘陵、陆 → 山地、台地一级）都 ≤ 8，只有高峰和高地上的丘陵会挡住中心（评审同意）。这是 2.5D 的固有代价；拾取总是选“看得见的那一格”（§8），被挡住的格子仍能点到它露出来的部分，以及用键盘方向键 / 地块检查器。

## 3. 地块：顶面、侧面、崖壁和海岸

- **顶面**：每种生物群系一张 24 px 半径的原创像素贴图（4 个变体），直接按扁六边形绘制（不是把平面贴图压扁），左上有一块亮面、右下一块暗面，配合光照方向。海水有浪花闪点，远洋更深，湖更亮。
- **侧面**：只有前面两条边（西南、东南）看得见。侧面高度 = 本格高度 − 该方向邻格高度，所以侧面刚好填满两格之间的落差，没有多余的过绘。西南面亮、东南面暗；顶上 1–2 px 是“草皮 / 沙层 / 雪层”的唇边，高崖中间加一道岩层线。每种生物群系一组侧面色（草原是褐土、沙漠是砂岩、雪原是蓝灰冰岩、火山是玄武岩加一道熔岩缝）。
- **海岸**：陆地的崖壁落到水面时，底部画一道白色浪花；水面上靠陆地的后方和左右边缘画虚线泡沫。
- **影子**：光从西北来。比本格高的西、西北、东北邻格在本格顶面靠那条边投下一条半透明暗带，落差越大越宽。高出邻格的格子在西北、东北边缘有一道 1 px 高光（边缘受光）。
- **河流**：在顶面上从中心画到相连的边；河流从崖上流下时，在侧面画一道瀑布和底部白沫。
- **竖立物件（广告牌）**：森林的松树和阔叶树、山地的岩峰、高峰的雪顶尖峰、火山锥（带熔岩和烟）、丘陵的两座小土包、草原的灌木 / 草丛 / 小树、沙漠的仙人掌和石块、雪原的雪松。物件按 y 排序后烘焙进每种“生物群系 × 变体 × 丘陵 × 高峰”的小画布，地面上带向东南的投影。
- **地标**：一块竖立的石碑，顶上是原来的地标徽记（字 + 颜色）。
- **领土**：边界线画在抬高后的顶面边上，内侧加一条阵营色的半透明带（文明系列式的领土描边），比平面版更容易看出“这一片是谁的”。

## 4. 深度排序

- 地块按行从后往前画（行号小的在后），同一行里各个环绕副本交错绘制，所以近处的高柱子总能盖住远处的东西，接缝两侧也一样。顶面、侧面、物件都在这个顺序里。
- 单位、城市、横幅、选中圈、移动范围等仍按原来的图层顺序画在地形之上（单位永远不被地形遮住，和文明系列一致，保证可读性）。
- 领土边界、改良、资源徽章在地形之后画，不参与遮挡（近处的高峰可能“压”在远处的一段边界线上，这是可接受的简化）。

## 5. 单位和城市：竖立的广告牌

- **单位**：脚下是一枚压扁的阵营色“棋子底座”（有厚度的深色边 + 顶面 + 原有的色盲安全花纹：斜纹 / 圆点 / 交叉纹），向东南投一个椭圆影子；宝可梦精灵站在底座上。阵营徽章、已行动 ✓、狂暴 !、晋升、HP 条照旧。敌对单位的红圈变成地面上的扁椭圆。
- **动画**：单位移动、弹道、商路光点按世界坐标插值，高度用“最近格及其邻格”的加权平均（`liftAtWorld`），所以走上山坡是平滑抬升，不会在半格处跳一下。
- **城市**（`town25d.ts`）：城市格铺一块石板广场（阵营色描边），上面是一组从南面略俯视的小房子：墙面、门窗、三排瓦片的屋顶（屋顶用阵营色，左亮右暗），房子数 = 2 + ⌊人口 / 2⌋（最多 9 座），按 y 排序。中心是议事厅；首都换成带垛口的塔楼和阵营色三角旗；有传说奇观的城市多一座金色尖塔。夜晚在夜色遮罩之上点亮暖黄色窗户和一圈淡淡的光晕。
- **设施区**：仍是原来的像素建筑图标（本来就是正面立着的建筑），格子底色按扁六边形画。
- **横幅**：原有的城市横幅上移，避开更高的城镇。阵营色描边不变。

## 6. 昼夜、天气、迷雾

- **夜晚**：仍是每帧一次的整图暗色遮罩（性能约束不变），之后再画城镇窗灯，所以夜里的城市是地图上最亮的地方。
- **天气**：天气范围的染色和标记照旧（扁六边形）。
- **迷雾**（记得但看不见的格）：遮罩覆盖顶面和看得见的侧面（同一个轮廓），颜色偏冷，斜线更淡。竖立物件超出本格的部分不被遮罩（例如雾里的松树树梢），这是可接受的简化；如果要完全一致，可以给物件烘焙一套“雾中”暗色版本（加入 base 缓存键）。
- **未探索**：最低的一层暗色格子，没有侧面；已探索的土地边缘露出完整的崖壁，像模型台的切面。

## 7. 东西环绕

- 世界压扁只改 y，`mapSpan`、`copyShifts`、`tileToScreen` 的横向逻辑不变，副本仍是左右并排。
- base / fog 层在 2.5D 下一次画完所有副本（行交错），所以接缝两边的高柱子遮挡关系正确。
- 邻格高度用规范化下标（`neighbourIndex25d` 会折回环绕列），接缝两侧的崖壁高度一致。

## 8. 拾取（屏幕 → 六角格）

`projection.ts` 的 `pickHex`：

1. 先按压扁后的世界做平面反算，得到“高度为 0 时”的格子。
2. 抬高的格子会显得更靠上，所以真正的格子在它前面 0–3 行、左右 2 格内；水和未探索更低，可能在后一行。
3. 候选按“从前往后”（行号大的先）排序，第一个其“柱体”（扁六边形顶面 + 看得见的西南 / 东南崖壁）包含该点的格子就是答案；都不包含时退回平面反算。
4. 返回像素平面的格子，调用方照旧 `hexToIndex` 折回环绕列。

渲染器保留上一帧场景的高度表，`renderer.pick(point, camera)` 平面模式下就是原来的 `worldToHex(toWorld(...))`。`main.ts` 的点击、右键、悬停提示、前往目标悬停、设施区选址都改用它。单元测试覆盖平面 / 环绕地图、三种缩放下每个格子的中心和崖壁中点。

## 9. 相机

- 俯角固定 0.75（见 §1）。缩放范围、拖动、滚轮、`F` 居中都不变；`fitCamera` 把地图高度乘上压扁系数，所以整图适配时 2.5D 地图能放得更大。
- 运镜（奇观揭幕、聚焦单位、世界页“定位”）用 `hexToWorld` 再减去该格高度（`renderer.lift`），对准抬高后的顶面（第二轮）。

## 10. 小地图（第二轮已实现，`render/minimap.ts`）

小地图保持**正上方平面**（每格 3–4 px 的色块 + 阵营边界 + 视口框），不画高度——小地图的作用是定位，2.5D 只放在主地图。视口框是压扁后的可见区域换算回平面世界的梯形 / 矩形。

## 11. HUD 与面板（设计，未在原型中实现）

原则：仍然“图标优先”；不遮挡行动栏、通知栏、开局目标卡、战斗卡；改的是框和质感，不是布局。

- **斜面像素框**：面板外框改成 2 px 硬边“斜面”——上、左边亮一级，下、右边暗一级，外面一圈 1 px 深色描边，四角各切掉 1 px（像素圆角）。只用 `border` + `box-shadow` 的 0 模糊硬阴影实现（不用 `filter` / 大模糊阴影，符合性能约束）。
- **标题条**：面板标题行加一条 3 px 的属性色 / 阵营色顶边，左侧一个 16 px 的像素图标（`ui-icons.ts` 已有）。
- **头像框**：单位面板、城市面板、领袖头像用“双线像素框”：外圈深色、内圈按属性色（宝可梦）或阵营色（城市 / 领袖），右下角 1 px 高光缺口，暗示立体。
- **属性色点缀**：单位面板的属性标签、招式按钮的左边条按 18 属性色；战斗卡左右两侧用双方属性色的竖条。
- **按钮**：主要按钮（下一回合、确认）做成 3 px 厚的“压下式”按钮：按下时顶面下移 2 px、厚度变 1 px。
- **地图工具条与图例**：工具条用同一套斜面框；图例按钮加 2.5D 模式下的“高度”说明（水 / 平地 / 丘陵 / 山地 / 高峰的小柱体图示）。
- 交付顺序：先改公共的面板框（`src/styles.css` 的面板 token），再按面板逐个替换；每一步跑 `npm run test:e2e:prod` 和截图对比。

## 12. 性能

约束（`handoff-combat-presentation.md`）：dense 场景 p95 不能超出噪声地变差；不用 `shadowBlur` 和大面积 `filter`。

- **已做**：每种地面贴图（生物群系 × 4 变体 + 远洋 / 湖 / 未探索）和每种物件组合各烘焙一次成小画布；城镇按“屋顶色 × 房子数 × 首都 × 奇观”烘焙。每格的开销是：1 次地面 `drawImage` + 0–2 个侧面多边形 + 0–1 次物件 `drawImage` + 一条描边（平面版是 1 次 `drawImage` + 一条描边 + 特征）。base 和 fog 两层沿用现有的“相机静止才建缓存”策略，缓存键里加了投影模式。
- **实测**：见文末“性能实测”。
- **下一步（若平移时的直接绘制超预算）**：把 base 层按 8×8 格切成世界空间的预渲染块（chunk），每块在“缩放档位”（例如 0.5 / 1 / 2）下渲染一次，带四周侧面和物件的外边距；平移时只做块的 `drawImage`。失效条件：块内任何格的生物群系 / 特征 / 领土边界变化，或缩放档位变化；领土边界可以单独一层，避免每次扩张都重建地形块。

## 13. 迁移

1. **现在**：`?render=25d` 或 菜单 → 地图视角（存进 `localStorage` 的 `pokeciv.renderMode`）。默认平面；所有读取平面坐标的测试不受影响。
2. **验收后**：默认改成 2.5D（`requestedRenderMode` 的缺省值一行），平面作为“平面”选项保留，也是测试的固定模式：Playwright 配置里给需要平面坐标的用例带 `?render=flat`（或在 `page.addInitScript` 里写 `localStorage`）。
3. **补齐**（第二轮已完成）：覆盖层锚点、相机聚焦、战斗卡锚点读取高度；联机页接入同一个设置；迷雾里物件的遮罩副本；HUD 斜面框（§11）；小地图（§10）。

## 第二轮（2026-11-19，评审后）

评审结论：近景很好，但默认缩放（1.5）下与平面差别弱，HUD 没变。决定：俯角固定 0.75；高峰可以挡住后面格子的中心；HUD 先改公共面板框，再改单位 / 城市面板。

**默认缩放下的纵深**（`projection.ts`、`terrain25d.ts`）

- **内陆台地**：按离已知水面的格数分三级（海岸 0、2–3 格 +3.5、4 格以上 +7），一整片草原也会出现等高线一样的台阶崖壁；只用玩家已知的地形计算，纯表现层。
- **崖壁对比**：西南面更亮、东南面更暗；每面崖壁底部三分之一加一道半透明暗带（环境光遮蔽），低处地面靠崖的一边是两级阴影带。
- **地块斜面**：每块陆地顶面内侧 1 px 斜面（西 / 西北 / 东北边亮，东 / 东南 / 西南边暗），平地也像一块块石板。
- **水和海岸**：水面降到 −8、颜色更深；落到水里的陆地崖壁顶上是一条湿沙唇边，底部白色浪花。
- **竖立物件**：默认缩放（≤ 1.5）放大 1.25 倍，到 2.6 倍缩放回到原尺寸（`propScale`）；山岩更高并向东南投下长影，森林更密，丘陵更饱满；城镇同样放大。
- **迷雾里的物件**：超出本格迷雾轮廓的部分（例如树梢）在地形块里画一张“已遮罩”的副本（在单位之下），轮廓内的部分仍由迷雾层遮罩，所以每个像素只遮一次。地形块按块记录迷雾签名，单位移动后只重建迷雾变化的块。

**补齐**

- `renderer.lift(hex)` / `renderer.anchor(hex, …)`：覆盖层锚点（战斗卡、推荐城址、屏幕内判断、奇观运镜）和相机聚焦（`F` / 单位聚焦 / 世界页“定位”）都对准抬高后的顶面；平面时高度为 0，结果与以前相同。地图上的前往路线、商路、弹道本来就用抬高后的格心。
- 联机页 `multiplayer.html` 读取同一个设置（`?render=` > `localStorage`），点击和设施区选址用 `renderer.pick`，“定位”按高度居中。
- **小地图**（`render/minimap.ts`，只在 2.5D 显示）：正上方平面，每格 4 × 3 px 色块（奇数行右移 2 px），已占领地块顶行是阵营色、其余半透明阵营色，记忆地形压暗，城市是浅色块加阵营色核心，视口是 1 px 浅色框加深色描边（东西环绕时画两段）。整数倍放大（标准图 2×）、`image-rendering: pixelated`。放在地图左侧、开局目标卡和底部提示 / 图例之间，层级低于战斗卡；矮屏或窄屏隐藏。点击或拖动跳转相机。底图只在命令号 / 玩家 / 可见格数变化时重画，每帧一次 `drawImage` + 8 次 `fillRect`。
**HUD 框**（`src/ui-25d.css`，平面和 2.5D 都生效，§11 的落地）

- 只改颜色、渐变和 0 模糊的内 / 外硬阴影：不加 `filter`，不改边框宽度，所以没有任何面板移动或改变尺寸；选择器以 `html` 开头，开发和生产构建的样式顺序不同也一样生效。
- **公共面板框**（`.panel`、`#economy`、`#unit-panel`、`.subpanel`，地图工具条、开局目标、图例、提示条）：1 px 深色描边 + 内侧 1 px 斜面（左上亮、右下暗）+ 2 px 硬投影，4 px 像素圆角。
- **标题条**（`.subpanel-head`、`.economy-head`、`.screen-head`）：顶上 3 px 强调色边（城市用阵营色，界面用金色），底下深浅两道硬线。
- **单位面板**：顶边、标题底色和头像内框用第一属性的颜色（18 属性，CSS `:has()` 读属性徽章，不改 TS）；工匠 / 商队 / 开拓队用金色。头像是双线像素框（深色外框 + 属性色内线），右下角 3 px 高光缺口，精灵脚下一块属性色的硬边椭圆地面。属性数值格是小斜面石板，HP / EXP 条是 1 px 描边的硬边条。

## 性能实测

方法与 `performance.spec.ts` 相同：Chromium、DPR 2、1280 × 900、dense 场景（1040 格、105 个可见单位）、上帝视角整图、20 帧预热 + 240 帧，同步 Canvas 2D 绘制时间。测量机是共享的 64 核开发机，测量时负载 30–60（后续在负载 120+ 时重测噪声太大，数值翻倍，不采用）。两轮交替测量（平面 / 2.5D / 平面 / 2.5D），p95，单位 ms：

| 场景 | 平面 | 2.5D（逐行合批前） | 2.5D（合批 + 世界空间分块缓存） |
| --- | --- | --- | --- |
| 相机静止（缓存命中） | 6.6–7.9 | 5.7–6.5 | 5.7–6.3 |
| 拖动（每帧平移 1 px） | 10.4–13.6 | 17.5–19.1 | ≈ 平面或更低（分块只做 `drawImage`；高负载下 11.5–19.7 对平面 37–41） |
| 直接绘制（不缓存，参考输出） | 12.5–14.6 | 18.1–22 | 同左（分块不影响无缓存路径） |
| 四场战斗 + 环绕，缓存 | 8.2–9.7 | 7.0–7.2 | ≈ 同左 |

结论：

- **玩家实际看到的帧**（相机静止、动画中、拖动）2.5D 不比平面慢：静止和战斗帧略快（2.5D 适配整图时缩放更大、可见格更少），拖动靠分块缓存不再每帧重画地形。
- **无缓存直接绘制**慢约 40%（每格多两面崖壁、影子、物件）。这条路径只在“缩放刚变化、相机还在动”的那几帧和 `cacheLayers: false` 的参考输出里出现。
- 没有用 `shadowBlur`、`filter`；所有新增绘制是 `drawImage`、`fillRect`、多边形填充和细线描边。
- `tests/browser/performance.spec.ts` 的 dense 场景新增一组 `projection25d`（直接 / 静止 / 拖动），每次全量 e2e 都会记录。

### 第二轮实测（2026-11-19）

方法同上（dense 场景：1040 格、105 个可见单位、上帝视角；Chromium、DPR 2、1280 × 900；20 帧预热 + 240 帧；p95，单位 ms），另加默认缩放 1.5（地图中部）。平面 / 2.5D 交替、三轮。测量时共享开发机负载很高（1 分钟负载 87–93），单次波动大，表中给三轮的最小 / 中位 / 最大。

| 场景 | 平面 | 2.5D（第二轮最终） |
| --- | --- | --- |
| 整图适配，相机静止 | 6.0 / 20.8 / 25.6 | 17.5 / 23.4 / 23.6 |
| 整图适配，拖动（每帧 1 px） | 20.7 / 29.0 / 37.9 | 6.0 / 15.1 / 19.2 |
| 缩放 1.5，相机静止 | 5.1 / 11.6 / 11.8 | 5.8 / 7.2 / 10.5 |
| 缩放 1.5，拖动 | 7.2 / 8.3 / 10.5 | 6.8 / 11.1 / 17.6 |
| 整图适配，无缓存直接绘制（参考） | 27.5 / 30.9 / 31.0 | 27.3 / 47.3 / 54.6 |

- 第二轮加大物件和台地后，缩放 1.5 下 2.5D 一度是平面的约 2 倍（负载约 106 时：静止 32–55 对 18–24，拖动 48–60 对 18–23）：可见的 ~17 个地形块每帧都要 `drawImage`，而块的上下留白（物件、崖壁）让重叠约 2.4 倍。
- 修正（`chunks25d.ts`）：可见块合成一张屏幕大小的图。静止帧 = 一次拷贝（和平面的 base 缓存一样）；拖动时把旧合成图按整数设备像素平移后拷贝，只在新露出的条带里画块，相机停下（或露出的条带超过屏幕 30%）时再重建合成图。单位底座按外观烘焙成小图（每个单位一次 `drawImage`，不再每帧 `clip` + 花纹）。
- 结论：静止和拖动在噪声范围内与平面持平（整图适配时 2.5D 更快）；无缓存直接绘制仍慢约 50%，只出现在“缩放刚变、相机还在动”的几帧和参考输出里。快速拖动时每越过约 30% 屏幕会有一帧重建合成图。
- 浏览器测试 `map-25d.spec.ts` 检查拖动中途和停下后的地形与同一相机下全新绘制的结果一致。
