# 传说图鉴 v15（对应《文明 6》奇观 / 巨作收藏）

- 状态：实现规格（草案，§7 的问题确认后定稿）。依据用户 2026-11-04 的答复：“传说宝可梦暂时不要加入战斗，建议做成图鉴或者科技收集品之类的素材”，以及 `docs/design/roster-v14.md` §1、§3。
- 版本：`gameplayVersion: 15`（schema 10，`rulesVersion: 'legends-v15'`），累积包含 v1–v14。v≤14 的存档、命令日志和回放逐字节不变：不初始化任何传说字段，不新增世代分来源，魅力和方针总量的计算不变。
- 只在有时代进程的对局里启用（`setup.eraProgression` 存在，与 v12 世代荣誉相同）。

## 1. 玩家看到的规则

### 1.1 传说记录是什么

- 每位传说宝可梦对应一条**传说记录**（收藏品，相当于文明的奇观 / 巨作）。记录**不是单位**：不能训练、捕捉、进化，没有战斗数值，不进野外刷新，不出现在地图战斗里。地图上能看到的只有“传说踪迹”标记（§1.2）。
- **全世界唯一**：每条记录只属于第一个满足条件的文明，之后别人不能再拿到。和奇观不同，记录不跟城市走：攻下对方城市不会夺走记录；文明被消灭后记录保留在名录里（标“已消失”）。
- **按自己的世代解锁**（与 v14 §3 一致）：传说的世代取原作图鉴世代。玩家当前世代 ≥ 该世代之后，条件才开始算。精简进程只有第 1–3 世代的 21 位传说，完整进程 43 位。
- 传说记录**不计入图鉴胜利**（图鉴胜利只数物种记录），也**不计分**（计分公式不变，见 §7 第 2 问）。

### 1.2 怎么获得（全部确定性、不看别人的迷雾信息）

| 来源 | 条件 | 判定 |
| --- | --- | --- |
| 踪迹 | 已研究「野外观察」，己方一只宝可梦在命令结束时站在该传说的踪迹格上 | 地图上的固定格，开局确定（§4.2） |
| 圣所石板 | 拥有对应圣所的石板（击败守卫后获得，见供奉、幻影与圣所） | 读 `tabletOwners`，石板只有一个主人 |
| 信仰 | 以该传说创立了信仰 | 读 `faith.faiths`，每位传说只能被一个信仰选走 |
| 内政成就 | 自己的状态达到门槛（图鉴、设施区、规章、人口、探索……） | 只读本文明状态 |
| 世代 | 第一个进入某世代，或处于黄金 / 黑暗世代 | 读自己的时代与世代荣誉 |
| 稀有事件 | 本命令里发生的特定事件（夜晚以某属性主动击倒、首次使用某时代能力） | 只读本命令的权威事件 |

- **判定时机**：每个命令结束后结算一次（在图鉴发现、世代荣誉之后，见 §4.3）。条件是状态型的：例如先拿到湖畔石板、后进入宝石时代，进入宝石时代的那次结算就会记录雷吉艾斯。
- **同时满足**：同一次结算里多个文明第一次同时满足同一条未被记录的传说时，取条件数值更高者（例如人口更多、科技更多），再相同取本轮行动顺序靠前者。传说按图鉴编号从小到大处理。
- 已被消灭的文明不能再获得记录。

### 1.3 与传说信仰的关系

- 信仰系统的五位传说（洛奇亚 249、凤王 250、盖欧卡 382、固拉多 383、烈空坐 384）**只能通过信仰获得记录**：以它创立信仰的文明，在自己达到它的世代时获得记录。它们不放踪迹、不挂别的条件，也不组成套组（一个文明只能创立一个信仰，套组永远凑不齐）。
- 信仰规则本身不变：v15 不改创立条件，也不按世代限制可选的传说（v9 起就能在初代选盖欧卡）。记录是信仰的“圣典”，祝福效果仍然只来自信仰。
- 没有人选的信仰传说，这一局就没有人能记录它。

## 3. 界面

- **传说页面**：顶栏新增入口「传说」（放在「时代」之后），点击打开全屏页面 `screen-legends`（`ScreenId` 增加 `'legends'`），Esc 或 × 返回地图。只在 v15 对局显示入口。
  - 顶部：已记录 / 本进程总数、套组进度条（每组成员头像，集齐后显示加成）。
  - 主体：按世代分组的卡片，只显示本进程的世代；卡片显示贴图、编号、名字、来源图标、条件、奖励和状态：**已记录（我）**彩色；**已被某文明记录**灰度并写出文明（信息不公开时写“已被记录”）；**可获得**黑色剪影；**需要第 N 世代**剪影加锁。自己可获得的内政条件显示进度（如“图鉴 12 / 15”“设施区 3 / 4 种”）。
  - 见过的踪迹卡片带「在地图上定位」，关闭页面并把镜头移到该格。
- **地图**：踪迹格在资源徽章层画一个带传说剪影的圆形徽章（与巢穴、圣所同层，样式区分），只画当前可见或记得的踪迹；被记录后从地图消失（看到该格时才更新）。悬停一行说明：“传说踪迹：急冻鸟（第 1 世代）”。
- **地块信息**：点击踪迹格，列出传说、世代、“需要研究野外观察 / 需要进入金银时代 / 派一只宝可梦站到这里即可记录”，以及当前不能记录的原因。

- **手册**：新增章节 `legends`（分组「世界」，标题「传说图鉴」，徽章 v15），名单、条件、奖励、套组表由 `guide/tables.ts` 从内容表生成；「系统总览」加一行，「快速上手」的顶栏入口列表加「传说」；「传说信仰」章节加一句“以哪位传说创立信仰，就获得它的传说记录”并链接；「胜利条件」注明图鉴胜利不数传说。

## 4. 状态、版本与迷雾

### 4.1 版本

- `usesLegendCodex(state) = state.expansion !== undefined && state.setup.eraProgression !== undefined && gameplayAtLeast(state.setup, 15)`。所有新逻辑都以 `state.expansion.legends` 是否存在为准，v≤14 永远不存在。
- `GameplayVersion` 加 15，`LATEST_GAMEPLAY_VERSION = 15`；`gameVersions` 加 `{ schemaVersion: 10, rulesVersion: 'legends-v15' }`。物种内容沿用 `roster-v14`（传说不是物种）。
- 世代荣誉的 `ERA_MILESTONES` 加 `legendRecorded: { name: '记录传说', points: 3 }`，只由传说模块计入；魅力 `appealPerRound` 和方针效果合计只在 `legends` 存在时加上传说部分。

### 4.2 状态与踪迹放置

```ts
// src/core/legend-codex.ts（内容表在 src/content/legend-codex.ts）
type LegendCodexState = {
  sites: Partial<Record<CodexLegendId, { tileIndex: number; position: Hex }>>;   // 被记录后删除
  claims: Partial<Record<CodexLegendId, { playerId: number; round: number }>>;
  seenSites: Record<number, CodexLegendId[]>;      // 每个玩家见过的踪迹（排序）
  knownClaims: Record<number, CodexLegendId[]>;    // 不公开的记录，玩家亲眼确认过的（排序）
  sets: Record<number, LegendSetId[]>;             // 已集齐的套组（排序）
};
```

- `CodexLegendId` 是英文 id（§2），其中 `hooh / lugia / groudon / kyogre / rayquaza` 与 `faith-legends.ts` 的 `LegendId` 同名，信仰条件直接对应。
- `initializeLegendCodex` 放在 `initializeExpansion` 最后（在 `initializePromotions` 之后），只放本进程世代内的踪迹（精简 7 个，完整 8 个）。
- 放置**不使用 `state.rng`**：用 `stableSeed(setup.seed, legendId, 'legend-site')` 给候选格排序（把 `civilization-systems.ts` 里的 `stableSeed` 移到 `rng.ts` 导出）。这样同一种子的 v15 地图、巢穴、霸主、资源与 v14 完全相同。
- 候选格：非海洋、离地图边缘 ≥ 1、不是城市 / 巢穴 / 霸主 / 树果 / 进化石 / 稀有树果 / 圣所格，离每座初始城市 ≥ 5 格，离已放的踪迹 ≥ 3 格；先按 §2 的首选群系，没有再用备选群系，再没有就放宽为任意陆地，最后把城市距离放宽到 3；仍然没有就抛错（与圣所一致，测试覆盖三种地图尺寸）。
- 踪迹不阻挡任何东西：可以在上面建城、修改良、建设施区，规则不新增拒绝原因。在踪迹上建城后，城里的己方宝可梦同样可以记录。

### 4.3 结算

- `recordLegends(before, after, events)` 在 `recordExpansion` 里排在 `recordEraHonors` 之后，读本命令的全部事件（含世界、发现、世代荣誉产生的事件）。`after.outcome` 已存在时不结算。
- 顺序：先更新 `seenSites` 和 `knownClaims`（视野与 `PlayerView.visibleTileIds` 同一集合）；再按图鉴编号处理每条未被记录的传说，算出每个存活文明的条件数值，按 §1.2 的规则决定得主；写入 `claims`、发放一次性奖励、通过 `creditEraMilestone(state, playerId, 'legendRecorded')` 把 3 分计入当前世代；最后检查套组。
- 每个条件实现为 `measure(state, playerId, events): number` 加门槛，布尔条件用 0 / 1，便于并列比较和界面显示进度。只读本文明状态或本文明作为主体的事件。

### 4.4 事件与迷雾

| 事件 | 字段 | 谁能看到 |
| --- | --- | --- |
| `LegendRecorded` | `playerId, legendId, source, reward` | 来源本身公开时 `public: true`（信仰：创立信仰本来公开；时代能力：`EraAbilityUsed` 本来公开；内政 / 世代：作为“历史时刻”公开，只说明成就，不带位置）；踪迹和圣所石板只发给本人 |
| `LegendSetCompleted` | `playerId, setId` | 只发给本人 |

- 事件不带坐标，名字不以 `World` 开头，`projectEvents` 现有规则即可过滤。
- **踪迹**：别人只有在看到该格时才知道踪迹已消失（写入自己的 `knownClaims`，名录显示“已被记录”，不显示是谁）。**圣所石板**：跟随 `observeCivilization` 的规则，圣所在视野内时才知道石板主人，从而知道对应记录属于谁。
- `observeLegends(state, playerId)` 给出 `{ entries, own, sites }`：`entries` 是每位传说在该玩家眼里的状态（我 / 某文明 / 已被记录 / 可获得）；`own` 是自己的记录、各条件进度、已集齐套组；`sites` 只含当前可见或 `seenSites` 里的踪迹，看不到的格子按记忆显示。别人的条件进度不出现在视图里。

## 5. AI

- **没有新命令**，因此不会产生新的被拒命令；记录全部是已有行为的结果。
- **踪迹**：视图里有自己可记录（已研究野外观察、世代够）且未知被记录的踪迹时，派离它最近的一只空闲宝可梦前往（优先侦察、快速、飞行定位；不动守城单位、圣所小队和交战中的前线单位），路径用现有 `paths` 查询，只走可达格；距离 > 12 格的不去；每个踪迹同时最多一只。
- **研究**：视野或记忆里有可记录踪迹且没有野外观察时，野外观察的研究优先级 +15。
- 其他条件不加专门权重（建设施区、规章、信仰、华丽大赛、时代能力都已有计划），避免为了收藏改变整体打法。
- AI 只读自己的 PlayerView。

## 6. 平衡与验收

- **v14 不变**：v14 固定 48 局（`node tools/district-smoke.ts 14 <目录>`）改动前后逐文件一致（`tools/compare-games.ts`）。

- **收集率**（不达标就调门槛和踪迹距离，不改信仰和圣所规则）：
  - 精简：每局被记录 6–15 条（共 21 条），每局至少 3 条；踪迹、内政 / 世代两类里每条传说的被记录率在 15%–95% 之间；信仰、圣所两类只报告，不调。
  - 完整：每局被记录 12–30 条（共 43 条）；第 7–9 世代每条被记录率 ≥ 5%。
  - 集中度：1v1 对局里收藏最多的文明占比中位数 ≤ 75%；套组每局平均集齐 ≤ 1.5 个，48 局里至少出现 1 次。
  - 来自传说的世代分占全部世代分 ≤ 15%。
- **报告字段**：每局记录数与来源分布、每条传说的被记录率和平均轮次、套组完成数、传说世代分占比、魅力中传说部分占比。
