# 传说奇观 v15（对应《文明 6》奇观，结合剧情）

- 状态：实现规格。依据用户 2026-11-04 的答复：“传说宝可梦暂时不要加入战斗，建议做成图鉴或者科技收集品之类的素材”，以及“传说宝可梦可以结合剧情，做成类似奇观”。
- 版本：`gameplayVersion: 15`（schema 10，`rulesVersion: 'legends-v15'`，内容沿用 `roster-v14`），累积包含 v1–v14。v≤14 的存档、命令日志和回放逐字节不变。
- 只在有时代进程的对局里启用（与 v12 世代荣誉相同）。

## 1. 玩家看到的规则

### 1.1 每位传说是一座奇观，配一段三章剧情

- 传说宝可梦**不是单位**：不训练、不捕捉、不参战。每位传说对应一座**传说奇观**（如“急冻鸟 · 冰封神殿”），在城市里用生产力建造。
- 每位传说有三章剧情：**第一章 · 线索**（发现线索时解锁）、**第二章 · 筑殿**（开始建造时解锁）、**终章 · 降临**（奇观落成时，全屏剧情卡）。
- **全世界唯一**：谁先建成归谁。别人正在建的同一座奇观立即作废，已投入的生产按一半折成金币退还（“奇观已被他人建成”）。
- **奇观跟着城市走**（和《文明》一样）：城市被攻占，奇观和它的效果一起易主。
- **按自己的世代解锁**（v14 §3）：传说世代取原作图鉴世代，玩家世代 ≥ 它才能开工。精简进程 21 座（第 1–3 世代），完整进程 43 座。

### 1.2 线索（第一章）

- 每个文明各自寻找线索，线索**不唯一**：几个文明可以同时拿到同一位传说的线索，然后比谁先建成。
- 线索来源与条件见 §2，全部是确定性的、只看自己的状态或自己参与的事件：
  - **踪迹**：地图上的传说踪迹格（开局固定，所有人共享）。研究「野外观察」后，己方宝可梦在命令结束时站在踪迹格上即得线索。
  - **圣所石板**：拥有对应圣所石板。
  - **信仰**：以该传说创立信仰（信仰五传说只能这样得到线索，也只有创立者能建）。
  - **成就 / 世代 / 稀有事件**：自己达成门槛、进入某世代、处于黄金/黑暗世代、自己做出某种战斗或首次使用某时代能力。
- 线索在世代不够时也会记下（剧情第一章解锁），等世代到了才能开工。

### 1.3 建造（第二章）

- 生产队列里新增“传说奇观”。条件：有线索、世代够、全世界还没建成、自己别的城市没在建同一座、城市满足**选址**（踪迹类传说要求城市工作范围内有对应群系，例如急冻鸟要雪原；其他传说不限）。
- 造价按世代：第 1–3 世代 110，第 4–6 世代 150，第 7–9 世代 190 生产。训练折扣不作用于奇观。
- 同一轮里两座城市都完成同一座奇观时，城市 ID 小的先结算（确定性）。

### 1.4 落成（终章）与效果

- 全世界公告“某文明建成了 急冻鸟 · 冰封神殿”（不公开城市位置）；建造者看到全屏剧情卡（贴图、标题、终章文字）。
- 地图上该城市的城市标签旁显示奇观标记。
- 效果：**所在城市**每轮产出加成（§2 每行），加上**整个文明**的小加成（走方针效果键，所有预览一致）。世代分 +4（v12 新增里程碑「建成传说奇观」）。
- 不计入计分、不新增胜利（默认，见 §7）。

## 3. 界面

- **传说页面**：顶栏入口「传说」（时代之后，只在 v15 对局显示），全屏 `screen-legends`，按世代分组的卡片：贴图（未得线索为剪影）、编号、奇观名、线索条件与进度、选址、效果、状态（未发现线索 / 有线索：可在哪些城市建造 / 世代不够 / 建造中：城市与进度 / 已建成：哪个文明，自己的写城市）。点卡片展开已解锁的剧情章节。
- **城市生产**：可建的奇观列在生产选项的“传说奇观”分组，显示造价、选址与效果；不可建的写原因。
- **剧情**：得到线索时动态里提示第一章；开工后传说页面解锁第二章；落成时全屏剧情卡（终章 + 贴图 + 题词，“继续”关闭）。别人建成时只在动态里写公告。剧情文字在 `src/content/legend-stories.ts`（原创）。
- **地图**：踪迹格画传说剪影徽章（与圣所同层）；建成奇观的城市标签旁显示金色奇观标记。
- **手册**：新章节「传说奇观」（世界组，v15），表格由内容生成；系统总览加一行。**审计**：`s-legend-wonders` 加检查器。

## 4. 状态、版本与迷雾

```ts
type LegendState = {
  sites: Partial<Record<LegendWonderId, number>>;            // 踪迹格（不移除，所有人可用）
  siteBiomes: Partial<Record<LegendWonderId, BiomeId>>;      // 实际放置的群系（决定选址）
  clues: Record<number, LegendWonderId[]>;                   // 每个文明已得线索（排序）
  wonders: Partial<Record<LegendWonderId, { cityId: number; builderId: number; round: number }>>;
};
```

- `initializeLegends` 在 `initializeExpansion` 最后；踪迹放置不用 `state.rng`（`stableSeed(seed, id)` 排序候选格），所以同种子的 v15 世界与 v14 相同。候选格：陆地（水君为与海洋相邻的陆地）、不是城市/巢穴/霸主/资源/圣所格、离初始城市 ≥ 5、离其他踪迹 ≥ 3；逐级放宽。
- 生产项 `{ kind: 'legend', defId: LegendWonderId }` 只在 v15 合法；`productionCost` 给出造价。完成时写 `wonders`，同时清掉其他城市队列里的同名奇观（按一半进度退金）。
- 线索在每个命令结束后结算（`recordExpansion` 中，世代荣誉之后），只读本文明状态与本命令里本文明作为主体的事件。
- 事件：`LegendClueFound { playerId, legendId }`（仅本人）、`LegendWonderCompleted { playerId, legendId, public: true }`（公开，无城市）、`LegendWonderLost { playerId, legendId, cityId, refund }`（仅本人）。开工就是一次普通的生产队列变更，第二章在传说页面随建造状态解锁。
- 视图：`{ sites（只含可见或已探索的踪迹格）, ownClues, wonders（公开：谁建成；自己的含城市）, building（自己在建的） }`。

## 5. AI

- 有线索、世代够、有合格城市、本文明没在建奇观时，在产出最高的合格城市队尾加一座奇观（多座可选时按图鉴编号最小）；城市受威胁时不加。别人建成后队列自动清掉，不产生被拒命令。
- 踪迹：视野或记忆里有自己还没线索的踪迹、已研究野外观察时，派最近的空闲侦察/快速/飞行宝可梦前往（≤ 12 格，每个踪迹最多一只）。

## 6. 验收

- v14 固定 48 局改动前后逐文件一致；v15 固定 48 局全部正常结束、0 异常、0 规则错误，两次运行一致；完整进程另跑一组。
- 结束方式相对 v14 最大变化 ≤ 20 个百分点，平均结束轮次变化 ≤ 10 轮。
- 精简：每局建成 3–12 座（共 21 座），每局得到的线索 ≥ 5；单个文明建成数占比中位数 ≤ 75%。完整：每局建成 6–25 座。
- 单元测试：v≤14 无 `legends`；放置不消耗 RNG；线索各类正反例；世代不够时等待；选址；唯一与退金；城市被占领后效果易主；迷雾（踪迹只在可见/记得时出现，私有事件不外泄）；回放一致。浏览器测试：传说页面、生产选项、落成剧情卡。

## 7. 默认决定（可改）

1. 奇观全世界唯一、跟城市走（用户：做成类似奇观）。
2. 不计入计分；不新增“集齐传说”胜利。
3. 信仰五传说只有创立该信仰的文明能得到线索并建造。
4. 剧情文字为原创中文短文，致敬原作设定，不照搬原作台词。
