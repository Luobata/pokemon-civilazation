# B1：M5-2 平衡调整方案（待用户决策）

> 本文只提出候选调整，不修改 GDD，也不宣称任何方案已达标。所有预期均为待模拟验证的假设；补丁字段已按 coder 交付的 `PATCH_SCHEMA` 与 `tools/patches/README.md` 对齐。

## 1. 基线与分析口径

唯一有效基线为 M5-2：100 个种子，200 局 1v1、100 局 1v3，共 300 局。1v1 同种子两腿相关，不当作独立样本；跨模式复用种子，也不增加独立种子数。

| 指标 | M5-2 | 目标 | 结论 |
|---|---:|---:|---|
| 全部征服终局 | 46/300 = 15.33% | ≥40% | 未达标 |
| 1v1 征服终局 | 36/200 = 18.00% | ≥40% | 未达标 |
| 1v3 征服终局 | 10/100 = 10.00% | ≥40% | 未达标 |
| 全部平均终局 | 94.24 轮 | 70–95 | 达标，但接近上限 |
| 1v3 平均终局 | 97.79 轮 | ≤95 | 未达标 |
| 扩张对好战 | 77.27% | 双方 40–60% | 未达标 |
| 扩张对保守 | 87.88% | 双方 40–60% | 未达标 |
| 保守对好战 | 63.24% | 双方 40–60% | 未达标 |
| 先手胜率 / 滚雪球 / 捕捉 | 52% / 61.35% / 6.36 次 | ≤55% / ≤75% / 3–10 | 已达标，需防回归 |

除汇总数据外，本文用 `/tmp/balance_m5_analysis.ts` 重放 300 局的 **213,726 条接受命令**，读取每次攻城前后的权威状态，统计真实伤害、反击、城市 HP、占城和首次达到军力门槛的轮数。完整输出为 `/tmp/balance_m5_analysis.json`。以下“首次 ≥N 单位”来自每轮末遥测，表示该轮末已经达到，不等于下一条命令必然可攻城。

## 2. 原因分析

### 2.1 不是“AI 完全不攻城”，而是推进漏斗层层损耗

M5-2 中，好战型有 4,046 次城市攻击（3,788 次敌城、258 次中立营地），保守型有 540 次敌城攻击；所以“征服低是因为好战从不攻城”不成立。扩张型 266 席确实全部零攻城，这是其冻结规则的预期行为。

好战型在全部 267 席中的推进漏斗：

| 阶段 | 席位/次数 | 说明 |
|---|---:|---|
| 从未宣战 | 34/267 | 另有 233 席至少宣战一次 |
| 宣战后从未攻城 | 101/267 | 占总席位 37.8% |
| 攻过城但未占任何城市 | 49/267 | 推进未能转化为占领 |
| 最终敌城攻击 / 敌城占领 | 3,788 / 194 | 每次占领平均约 19.5 次总敌城攻击；按单次占领连续攻击段计为 13 次中位数 |
| 大本营占领 | 115 | 1v1 为 29，1v3 为 86；1v3 还需淘汰其余多家才终局 |

保守型 540 次敌城攻击产生 31 次占领，其中大本营 24 次。1v1 的 36 次大本营占领与 36 局征服一一对应；1v3 的 103 次大本营占领只产生 10 局征服，说明多人局还存在“攻下一家后未能清完其余对手”的第二层转化问题，不能只用单次攻城 buff 推断多人终局。

### 2.2 城市 HP 使单次占领需要约 14 次攻击，建筑进一步拉长大本营战

真实攻城事件显示：

| 性格（1v1） | 攻城伤害均值/中位数 | 反击均值 | 城市最大 HP 中位数 | 单次占领攻击段中位数 |
|---|---:|---:|---:|---:|
| 好战 | 10.02 / 10 | 1.66 | 140 | 14 |
| 保守 | 12.20 / 12 | 1.53 | 200 | 15.5 |

全部好战攻城的平均伤害为 10.39，城市最大 HP 均值为 149.65；每次占领连续攻击段平均 13.05、中位数 13。城市反击累计造成好战 44 次、保守 4 次单位击坠/休养，带来三轮战力真空和维护费；但反击不是唯一瓶颈，HP 与攻击次数的证据更直接。

具体路线 `1v1-11-0`（扩张对好战）：好战第 6 轮宣战，第 29 轮首次攻城，第 34/40/47 轮依次占普通城，直到第 72 轮才以第 18 次攻击攻下 HP 上限 200 的大本营。该例支持“宣战→接触→逐城推进→高 HP 大本营”的时间链，不能用单次战斗伤害解释全部 23 轮接敌延迟。

### 2.3 “战斗单位 ≥4”使部分好战席永远无法推进，但不宜只删门槛

好战型首次达到 4 个战斗单位：

- 全部席位：170/267 达到，未达到 97 席；达到者的中位数为第 27 轮。
- 1v1：89/134 达到，未达到 45 席；达到者的中位数为第 26 轮。
- 若门槛改为 3：全部 216/267 达到，未达到降至 51 席，中位数提前至第 21 轮；1v1 为 109/134，未达到降至 25 席，中位数同为第 21 轮。

因此，4→3 能扩大可推进席位并提前约 5–6 轮，但仍有 51/267 席连 3 个单位都未达到。它是可验证的小步杠杆，不应被描述为完整修复。

### 2.4 好战型的扩张门槛与军力经济互相卡住

当前好战型只有城市 ≥3 才继续生产开拓队。M5-2 中：

- 好战 210/267 席从未再生产开拓队，81/267 席没有建过新城；扩张只有 2/266 席从未再生产，6/266 席没有建新城。
- 1v1 终局平均城市数：扩张 5.20、好战 2.08、保守 2.60。
- 1v1 终局平均战斗单位：扩张 8.29、好战 3.32；平均维护费分别为 14.77 和 6.01。

这与“先到 3 城才生产开拓队”的规则一致：好战在 1–2 城时无法像扩张一样持续增加城市产出，军力、金币和后续推进一起受限。不能由相关性断言唯一因果，但 125/134 个 1v1 好战席没有后续开拓队生产，足以把 `settlerMinCities` 列为优先实验变量，而非先全面降低维护费。

### 2.5 扩张优势主要是城市分，且没有攻城反击成本

1v1 终局分项均值：

| 性格 | 城市 | 人口 | 物种 | 科技 | 击坠 | 总分 |
|---|---:|---:|---:|---:|---:|---:|
| 扩张 | 5.20 | 18.08 | 4.52 | 6.98 | 8.02 | 879.44 |
| 好战 | 2.08 | 9.44 | 2.07 | 4.67 | 9.19 | 424.75 |
| 保守 | 2.60 | 11.13 | 2.30 | 5.94 | 7.72 | 517.45 |

扩张胜出的 109 局中，胜者相对败者平均领先 494.19 分，其中城市分领先 354.13；从总分差中扣除城市分差后剩 140.06（该差值包含「联盟规章」乘算影响，不冒充其他分项的原始求和）。城市每座 ×100 是最主要的直接计分来源。扩张同时有 6432 次普通攻击，并非“完全不战斗”；但其 132 个 1v1 席零城市攻击、零城市反击击坠，因此不承担攻城特有风险。应表述为“没有攻城反击成本”，而不是“从不损失单位”。

## 3. 可调整杠杆

### 3.1 内容数值

| 杠杆 | 当前 → 候选 | 预计影响（假设） | 主要风险 | D15 影响 |
|---|---|---|---|---|
| 城市基础 HP | 100 → 80；每非大本营建筑 +20 不变 | 占城攻击次数下降，征服提前；1v3 轮数下降 | 过早终局、防守方过弱、滚雪球升高 | 不改物种，不改变单位间克制上限；无需因该项重跑全对全 |
| 每建筑 HP | +20 → +15 | 主要针对后期高 HP 大本营 | 建筑防御价值下降，与基础 HP 同调会叠加过强 | 同上 |
| 城市反击 A | 30 → 24；杰尼龟 34 → 28 | 减少攻城方休养和维护损耗 | 城市过易、反击存在感下降 | 不改物种数值；无需全对全，但需城市反击定向测试 |
| 投石改装攻城倍率 | ×1500 → ×1750 | 强化攻城定位和后期征服 | 科技成为必选，普通兵种价值下降 | 非物种基础值；仍需攻城定位回归，不声称 D15 单位对局已重跑 |
| 城市计分 | ×100 → ×80 | 直接缩小扩张的城市分优势 | 建城价值下降，可能把优势转向科技或击坠 | 无 |
| 阶段维护费 | 1/2/3 → 1/2/2 | 缓解高阶军力经济压力 | 所有性格同时受益，可能反而强化扩张大军 | 无；不作为首轮推荐 |
| 占城后 HP | 50 → 60 | 帮助连续推进，尤其 1v3 | 占领滚雪球、守方无法夺回 | 无；不作为首轮推荐 |

若后续改为物种 HP/A/D/P、阶段或克制数值，必须按 D15 重跑全对全；本推荐方案刻意不改这些字段。

### 3.2 AI 性格规则

| 杠杆 | 当前 → 候选 | 预计影响（假设） | 风险 |
|---|---|---|---|
| 好战攻城军力 | 己方战斗单位 ≥4 → ≥3 | 1v1 可达到门槛者由 89/134 增至历史轨迹中的 109/134，首次达标中位数 26→21 轮 | 小队送死、城市反击损耗增加；历史轨迹只证明门槛覆盖，不证明新轨迹胜率 |
| 好战宣战车力比 | 己方 ≥对方 ×1.5 → ×1.25 | 更早宣战、更早接敌 | 过早宣战、军力被多个对手消耗 |
| 好战后续开拓队城市门槛 | 城市 ≥3 → ≥2 | 解开 1–2 城时的扩张/产出瓶颈，缩小城市分差距 | 军事训练被经济分流，可能推迟首次 ≥3 单位 |
| 保守反攻倍率 | 己方 ≥对方 ×2 → ×1.75 | 增加保守实际反攻和征服 | 改变“保守”定位，可能提高其胜率过头 |
| 扩张攻城规则 | 从不 → 满足高优势时允许 | 直接提高征服 | 同时强化当前最强势性格；不推荐 |

首轮只调好战型的前三项；不同时放宽保守与扩张，以便归因。

### 3.3 规则结构

| 杠杆 | 当前 → 候选 | 评价 |
|---|---|---|
| 征服判定 | 大本营失守淘汰 → 占领全部城市才淘汰 | 会更难征服，与目标相反；不推荐 |
| 大本营防御结构 | 与普通城同公式 → 大本营固定较低 HP 或攻城易伤 | 可精准加速终局，但增加新规则与 UI 解释成本；首轮不新增结构 |
| 默认轮上限 | 100 → 120 | 可能提高征服率，但会进一步抬高平均终局轮数，掩盖而非解决节奏问题；不推荐 |
| 默认轮上限 | 100 → 90 | 迫使更早决战的说法没有机制保证，只会把部分对局直接变计分；不推荐 |

## 4. 推荐组合（按优先级）

### 方案 A：先释放好战型的军力与扩张门槛

只改 AI，不改战斗、物种、计分或 D15：

```json
{
  "ai": {
    "aggressiveSettlerCities": 2,
    "aggressiveSiegeUnits": 3,
    "aggressiveWarStrength": 1250
  }
}
```

**假设**：攻城参与席增加、首次推进提前，好战城市数和终局军力改善；征服率与好战两组配对胜率向目标移动，1v3 平均轮数下降。它不直接削弱扩张，因此若扩张仍靠计分大幅领先，不强行继续下调好战门槛。

**放行假设而非承诺**：三项未达标配对均回到 40–60%，征服率上升且平均轮数不恶化；若征服仍明显低于 40%，进入方案 B，而不是再把军力门槛降到 1。

### 方案 B：方案 A + 小幅城市 HP/计分调整

在 A 的基础上增加：

```json
{
  "balance": {
    "city": {
      "baseHp": 80,
      "buildingHp": 20
    },
    "score": {
      "cities": 80
    }
  },
  "ai": {
    "aggressiveSettlerCities": 2,
    "aggressiveSiegeUnits": 3,
    "aggressiveWarStrength": 1250
  }
}
```

**假设**：以好战平均约 10 点攻城伤害估算，无建筑城市从约 10 次降到约 8 次攻击；后期城市仍保留建筑加成。城市 ×80 可缩小扩张的计分差距。两项合用以征服、三组配对和 1v3 轮数同时达标为目标，但不预测具体通过率。

**风险**：A 的行为变化与 HP/计分同时出现，归因粒度较粗。因此必须先有 A 的同种子结果，再跑 B；若 B 出现过早终局或滚雪球超过 75%，回退为 `balance.city.baseHp=100` 单独验证 `balance.score.cities=80`，不要继续叠加反击削弱。

## 5. coder 验证计划

### 5.1 补丁接入与基本保障

1. 以上 JSON 已按 coder 交付的 `tools/patches/README.md` 与 `PATCH_SCHEMA` 字段编写：AI 军力比使用千分比 1250，城市与计分使用 `balance` 路径。design 不自行修改模拟器。
2. 每套补丁先跑确定性：同 seed、同 setup、同 patch 双跑，命令、终局、telemetry 和摘要完全一致；再跑现有 core/AI/tools 单测、构建与 lint。
3. 确认补丁只覆盖指定字段；未列出的内容数值、AI 收益、种子、地图、席位编排与统计口径保持 M5-2 一致。
4. 城市 HP 变化需要补城市最大 HP、占城恢复、杰尼龟反击不受影响等定向测试；AI 门槛变化需要 2/3/4 单位和 2/3 城的边界测试。

### 5.2 模拟顺序

1. **探索批**：A、B 分别跑与 M5-2 完全相同的 100 种子（300 局），先比较同种子变化，不把两腿当独立样本。
2. **追加批**：按 D18 对征服、1v3 轮数、三组配对和先手胜率追加 100 个新相关种子；若任一指标距阈值不足 5 个百分点，也追加。报告探索/追加/合并结果，不能只用探索批宣称验收。
3. **失败时做单变量归因**：从 A 中分别跑 `ai.aggressiveSettlerCities=2`、`ai.aggressiveSiegeUnits=3`、`ai.aggressiveWarStrength=1250`；从 B 中分别跑 HP 与计分覆盖。不要一次引入更多杠杆。
4. **验收批**：最终候选按 GDD 发布前要求跑至少 200 个新种子，并保留 aborted、defect、fog 拒绝和命令上限分类。

### 5.3 每批必报指标

- 原目标全表：征服、平均终局、先手、无属性优势击坠、滚雪球、捕捉、aborted/defect；同时看 1v1/1v3 和 30 轮前终局数。
- 三组两两胜率及 Wilson95%，1v3 性格胜者份额只按原编排解释。
- 攻城诊断：达到 3/4 单位轮数、宣战/首次攻城/首次占城轮数、每次占领攻击段、城市反击击坠、普通城与大本营占领、1v3 清场转化。
- 经济诊断：后续开拓队生产、城市数、人口、科技、终局军力和维护费，检查好战 buff 是否反而被扩张吸收。
- 守护阈值：先手 ≤55%、滚雪球 ≤75%、每局捕捉 3–10、无属性优势击坠 >25%、aborted ≤5%；任一原达标项退化都要报告，不能只展示征服提升。

本方案不改物种数值，因此没有因本方案触发 D15 全对全重跑。若 coder 或用户另改物种 HP/A/D/P、阶段、克制或免疫，必须额外执行全对全校验，不能用 300 局模拟替代。

## 6. 待用户拍板

1. **是否先只调 AI？** 选项：A（推荐，先验证三项好战门槛）/ 直接 B / 暂不调。推荐 A，因为不改玩家可见数值，且能隔离 AI 门槛影响。
2. **城市是否应更容易攻下？** 选项：基础 HP 100→80（B 推荐候选）/ 保持 100 / 只改投石倍率。推荐先保持 A 不变，A 不足时选 80，避免过早终局。
3. **城市计分是否下调？** 选项：×100→×80（推荐仅在配对仍失衡时）/ 保持 ×100 / ×70（更强，暂不推荐）。这是计分方向决策，不应由模拟器自动决定。
4. **好战是否应更激进？** 选项：军力 4→3、军力比 1.5→1.25（推荐）/ 只改其中一项 / 保持。用户需确认“更主动的小队战争”符合性格方向。
5. **好战能否更早扩张？** 选项：城市 3→2（推荐）/ 保持 3。该改动可能让好战更像扩张，需要用户接受性格差异被弱化一点的风险。
6. **是否调整默认轮上限？** 推荐保持 100；不以 120 掩盖节奏，也不以 90 强行增加计分局。只有用户明确想改变整局时长时才另立方案。
7. **保守与扩张是否也要改？** 推荐首轮不改。保守 ×2→×1.75、扩张允许攻城都可能继续强化征服，但会模糊归因并改变性格定位。

## 7. 测试夹具修正记录

`tests/browser/fixtures/diplomacy.ts` 的 score 局不再手动传 `[0]`，改为不传 winners，让 `finishGame` 按完全并列规则产生共同胜者；对应 E2E 新增两家均在 `outcome.winners` 且摘要显示“文明 1、文明 2”的断言。征服和玩家失败夹具仍分别显式使用 `[0]` 与 `[]`。
