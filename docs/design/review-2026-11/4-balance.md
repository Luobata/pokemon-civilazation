# 评审 4：平衡体系还可以做什么（2026-11-07）

> 范围：只评审平衡流程、度量和调参方向，不改代码。所有数据都是 AI 对 AI，来自 gameplay v20、精简时代、4 方同性格。
> 本次实测脚本是放在 `/tmp/balance-probe/` 的一次性脚本（导入 `tools/leader-balance.ts` 的 `simulateLeaderCase`，每轮采样一次），不进仓库。

## 0. 结论速览

1. 现在的验收是**相对上一版的漂移检查**（结束方式变化 ≤20 个百分点、平均结束轮变化 ≤10 轮），没有绝对目标。每步都过线，但累计已经明显偏移：v16→v20 平均结束轮 93.0 → 79.4，征服 4 → 14/48。
2. 固定 48 局只跑 **24×16 / 100 轮**，可默认开局是 **40×26 / 200 轮**。大图实测（下文 §2）和小图差别很大：征服 29% → 17%，图鉴 2% → 33%，积分（打满轮数）35% → 2%，**一半对局在第 100 轮前结束**，第 101–200 轮基本没人玩到。
3. 冒烟只取 `rotation < 4`，9 位领袖里**小椿、坂木一次都没上场**，乔伊每组 4 局都在，大木和大吾每组只出现 1 局（`tools/district-smoke.ts:12`）。按这批数据算的领袖份额本来就不可比。
4. 大图跑 48 局只要约 4 分钟（12 核并行，单局 30–70 秒）。**把大图当正式平衡门槛的成本很低**，应该直接改。
5. 最该先调的三处：城市防守战斗力不随时代提高（`src/core/strength.ts:81`）、AI 开拓优先级太低导致大图每个文明平均只有 3.6 座城（`src/ai/plan.ts:193`）、各胜利门槛不随地图和轮数缩放。

## 2. 本次实测：同一批 48 局，小图 vs 大图（v20，种子 31–34，精简时代）

小图一栏和 v20 文档的官方结果一致（征服 14/48、平均 79.4 轮），说明脚本口径没问题。

按出场次数折算的领袖胜率（基准 25%；小椿、坂木 0 场）：

| 领袖（出场） | 大木(12) | 渡(24) | 君莎(36) | 乔伊(48) | 小刚(36) | 小霞(24) | 大吾(12) |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 小图 | 0% | 17% | 3% | 35% | 47% | 13% | 50% |
| 大图 | 25% | 33% | 11% | 29% | 33% | 17% | 25% |

读法：
- 大图上积分胜利几乎消失、图鉴变成第一大胜利方式，是因为图鉴目标（18 种 + v14 的 5 种，`src/content/world-systems.ts:74`）、大赛门槛（500 魅力 / 领先 1.5 倍，`src/core/contests.ts:19`）、冠军（第 40 轮开始、每 20 轮一届、2 次夺冠就赢，`src/content/civilization-systems.ts:103`）都是固定值，和地图、轮数无关。12 项科技在第 100–140 轮就研究完，精简时代在第 67 轮左右走完，后半局没有新的进程内容。
- 小图的滚雪球明显更强（第 30 轮领先者赢 62.5%），大图翻盘多。说明"征服太多"主要是小图问题，大图的问题反而是**扩张不足、提前结束**。
- 领袖：君莎在两种尺寸都垫底（3% / 11%），小刚在小图很强。领袖平衡目前暂停，这里只指出抽样设计本身就有偏差。

## 3. 平衡工具箱提案

### 3.1 指标（每局都输出，按局写入 `metrics.jsonl`）
- 节奏：第二座城 / 第四座城的轮次，第二、第三世代到达轮，科技研究完的轮次，首次宣战 / 首次攻城 / 首次失城的轮次。
- 曲线（每 10 轮一个快照）：城市数、人口、粮 / 产 / 金 / 研四项产出、科技数、军队规模和各兵种数量、分数。
- 滚雪球：第 30 / 60 / 100 轮领先者的最终胜率；领先者更替次数；"在第 X 轮已经决出胜负"的比例（最终胜者从 X 轮起一直领先）；分数基尼系数。
- 结局：各胜利方式份额（Wilson 区间）、结束轮分布（P10 / 中位 / P90）、打满轮数的比例、被消灭的文明数。
- 系统贡献：每个系统"用量最多的文明胜率 − 基准"；兵种克制命中率（训练的单位能克制当前主要敌人兵种的比例）；水面单位占比只算沿海城市多的文明。
- 领袖与性格：按出场次数折算的胜率，**9 位领袖全部轮换**（9 种座位轮换，或者每局随机抽 4 位并固定种子）。

### 3.2 命令行工具
- `tools/balance-run.ts --gameplay 20 --size 40x26 --rounds 200 --eras simple|full --seeds 31-38 --players 4 --mix same|mixed --workers 12 --patch p.json --out dir`：在现在的 `simulateLeaderCase` 外面加一层子进程并行，写出逐局 JSON、`metrics.jsonl`、`curves.jsonl` 和 manifest（git head、补丁哈希）。
- `tools/balance-report.ts dir [--baseline dir]`：生成 Markdown 报告，包括结局表、曲线（按轮的均值与 P10 / P90）、领袖与性格表、§5 验收线的通过 / 失败，以及和基线的差值和区间。
- A/B：`--baseline` 用**固定锚点**（建议把 v20 大图结果冻结为 `anchor-v20`），而不只是上一版；同时报告"相对上一版"和"相对锚点"两列，累计漂移就能看见。
- 敏感度扫描：`tools/balance-sweep.ts --param balance.city.defense=50,60,70 --param ai.aggressiveWarStrength=1250,1500`，每个取值跑 48 局大图，输出"参数 → 征服份额 / 平均结束轮 / 第 60 轮领先者胜率"的响应表。前提是让 `simulateLeaderCase` 接收 `{ content, ai }` 覆盖，并把 `FAITH_RULES`、`CONTEST_RULES`、`STRENGTH_RULES`、`WORLD_DEFINITIONS`、冠军参数挪进 `Content`，否则大部分新系统扫不了。
- 系统开关对照：`--disable faith|contest|legends|network|roles` 跑同一批种子，衡量每个系统对结束方式和节奏的影响（AI 不使用该系统即可，规则不变）。

### 3.3 脚本策略（新增 AI 性格，只用于测试）
| 策略 | 做法 | 用来检验 |
| --- | --- | --- |
| 速推 | 只出 2 座城，全部产能出兵，第 25 轮前宣战 | 早期防守是否站得住；城防数值 |
| 铺城 | 开拓优先级最高、城数上限 = 地图面积 / 80 | 扩张是否该被惩罚（满意度、维护费） |
| 高塔 | ≤ 4 座城，设施区和奇观拉满 | 少城能不能靠质量赢 |
| 信仰 / 大赛 / 图鉴专精 | 只追一种非军事胜利 | 每种胜利最快多少轮能达成（门槛下限） |
混合对局：1 个脚本策略 + 3 个默认 AI，看脚本策略的胜率。哪种策略长期 > 50%，就说明有一条"最优解"路线。

## 5. 验收线更新（建议）

两档：
- **快速回归（每个版本必跑，保持现状）**：24×16 / 100 轮固定 48 局；只管 0 异常、逐字节一致、旧版本逐文件一致。漂移线保留，但改成同时对比上一版和锚点，相对锚点累计 > 20 个百分点就报警。
- **平衡门槛（新增，默认开局）**：40×26 / 200 轮、精简时代，8 个种子 × 9 种领袖轮换 × 3 性格 = 216 局（12 核约 12–15 分钟）；完整时代另跑 4 个种子做抽查。

| 项目 | 线 | v20 大图现值（48 局） |
| --- | --- | --- |
| 任一胜利方式份额 | ≤ 35% | 图鉴 33% ✓（边缘） |
| 胜利方式多样性 | 至少 5 种 ≥ 5% | 4 种（积分 2%、信仰 4%）✗ |
| 征服份额 | 10%–30% | 17% ✓ |
| 打满轮数（积分）份额 | 10%–25% | 2% ✗ |
| 中位结束轮 | 130–160 | 101 ✗ |
| 第 80 轮前结束 | ≤ 15% | 13/48 = 27% ✗ |
| 第 60 轮领先者最终获胜 | ≤ 55% | 50% ✓ |
| 每局领先者更替 | ≥ 3 | 7.4 ✓ |
| 每文明峰值城数（全部 / 扩张型） | ≥ 5 / ≥ 7 | 3.6 / 5.2 ✗ |
| 第二座城中位轮 | ≤ 15 | 6 ✓（但 26/192 从未有第二座城 ✗，线：≤ 5%） |
| 兵种：最高单项 / 水面 | ≤ 35% / ≥ 4% | 远程 34.9% ✓ / 2.3% ✗ |
| 每位领袖胜率（按出场折算） | 15%–35%，9 位全部上场 | 君莎 11% ✗，2 位未上场 ✗ |
| 每种性格在混合局里的胜率 | 20%–45%（新增混合局后） | 未测 |
| 0 异常 / 0 中止 / 重放一致 | 硬门槛 | ✓ |

样本说明：48 局时 30% 份额的 95% 区间约 ±13 个百分点，216 局约 ±6，所以门槛档要用 216 局；快速档的 48 局只适合抓回归，不要拿来下平衡结论。人类试玩出来的数据（速推、铺城是否过强）以后补进 §3.3 的脚本策略，是目前完全缺失的一块。
