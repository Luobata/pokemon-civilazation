### 0.2 实测：真实对局里的对战（v24，40×26 / 200 轮）

脚本在 `/tmp/depth-v26/`（源码树外，只读调用 `createGame` / `planNext` / `step`）：重放 `gate-v24-ai` 门槛里种子 31–38 × 三种性格、轮换 0 与 4 的 48 局（与门槛逐局相同的设置和代码），在每条 `ChallengeGym` / `ChallengeGuardian` / `ChallengeEliteFour` 命令前记下双方阵容（物种、当前 HP、攻防、经验），在 `ChampionshipResolved` 前记下各家报名队伍；再用同一个 `damage()` 公式重放：①现在的混战；②本稿第 2 节的“单打接力”原型，对挑战方的**每一种出场顺序 / 人选**各跑一次。另每 10 轮记录金币、人气、在建传说、进化、劲敌结果。

**样本**：48 局里已完成的 36 局（种子 31–38 × 三种性格 × 轮换 0 / 4 中，最长的 12 局在写稿时还没跑完，所以后期样本偏向较早结束的对局）。结局 华丽大赛 15、冠军赛 10、信仰 6、征服 3、图鉴 2；结束轮中位 120。

| 指标 | 值 |
| --- | --- |
| 道馆挑战 | 427 次，AI 胜 375（87.8%）；首枚徽章中位第 19 轮 |
| 道馆双方只数 | 2 打 1：153、3 打 2：113、3 打 1：102、2 打 2：35、3 打 3：15、1 打 1：8、2 打 3：1——**挑战方人多的占 86%** |

| 联盟大会：玩家队伍对 NPC 的比赛 | 548 场；顺序翻转结果：混战 31（5.7%），单打接力 **162（29.6%）** |
| 圣所守卫挑战 | **886 次，胜 1**；31 个文明挑战过；挑战队伍 HP 中位只剩 20%；同一文明最长**连续 83 轮**每轮挑战 |
| 四天王 | 0 次（没有文明集齐 8 枚徽章） |

读法：

- **道馆的决策为什么薄**：AI 只在战力比 ≥ 1.25（有属性优势 ≥ 1.1）时挑战，所以实际对局几乎都是 2–3 只打 1–2 只的碾压局；在这种局里**任何规则下顺序都几乎不重要**（单打接力也只有 3.1% 局翻转）。原作道馆有味道，是因为双方人数接近、属性互克。所以 v26 的道馆要**同数对战**（你带的只数 = 馆主只数），这时**选谁 + 顺序**能翻转 35.8% 的对局。
- **联盟大会天然是 6 对 6**：同样的队伍，混战里顺序能翻转 5.7% 的对 NPC 比赛，单打接力里是 29.6%——顺序第一次成为真正的决策。
- **圣所守卫打不赢**：886 次挑战**只赢 1 次**（216 局门槛里也没有一局起源胜利）。原因是守卫的 HP、攻、防同时 ×3–4；AI 还按“满血战力 ≥ 620”判断，不看当前 HP，于是同一支残血小队**每轮都去挑战**（同一文明最长连续 83 轮，挑战队伍 HP 中位 20%）。这是现有规则缺陷，v26 一并修（2.2 节）。
- **混战的“打最打不动的人”**：改成集火只翻转 3.7% 局，因为局面本来就一边倒。v26 用新对战层整体替换，不单独修。

## 2. P1：宝可梦对战（`content.teamBattles`）

### 2.1 规则：单打接力（`src/core/team-battle.ts` `resolveTeamBattle`，选择 1A）

- 双方各有一个**出场顺序**。在场的是各自顺序里第一个还没倒下的。倒下的立刻由下一位补上（不占回合）。
- **每回合**：
  1. **换人检查**（自动、规则公开、每方每场最多 1 次）：在场者会被对手 ≥ ×2 命中、自己打对手 ≤ ×1，而替补里有承受对手 ≤ ×0.5 的成员时，换上顺序里第一个这样的成员；换上的这回合不出手，承受对手这一击。
  2. **先手**：兵种速度档 快速 4 · 侦察 / 飞行 3 · 远程 2 · 近战 / 水面 1 · 攻城 0；同档比攻击；再同则挑战方先。
  3. **出手**：攻击方在自己的属性（主、副，以及招式学习器的 1 个，5.1 节）里选**对当前对手倍率最高**的一个；伤害 = `damage(攻 + 历练, 防 + 历练, 威力, 倍率, 地形, 85–100)`，即地图战斗与 v24 `simulateBattle` 的同一个整数公式；属性研究的 ×2.2 照旧对双方生效。
- **历练**（经验在战斗里第一次有用）：每 50 经验 攻 / 防 +1，最多 +5。进化后经验清零，历练也清零——“进化还是先练满”成为一个小取舍。
- **结束**：一方全部倒下；或 60 回合上限，按剩余 HP 比例之和判（同 v24）。
- **地形**：道馆 / 圣所 / 劲敌所在格的群系（同 v24 的 `terrainMultiplier`）；四天王与大会在“会场”（中性 100）。
- **写回**：参战宝可梦 HP = max(1, 战后 HP)，花掉行动（同 v24）。四天王与大会：**场间恢复已损失 HP 的 50%**（四天王已是这样；大会现在是战损累计，统一）。
- **胜负主要由阵容决定**：85–100 的随机只在势均力敌时起作用（原型里多数对局的估计胜率是 0% 或 100%，3.1 节的单挑表也是）。这正是要的效果：克制格、人选和顺序就是决策。可选旋钮「会心一击」（1/16 概率伤害 ×1.5，原作的“击中要害”）让接近的对局有悬念、回放有高光；默认关（本稿的实测都不含它），试玩后再定。
- **随机**（选择 2A）：结算时从 `state.rng` 抽一个 31 位种子（`randomBelow(state.rng, 2 ** 31)`），写进回放记录。玩家和 AI 都**不能预知**结果，预览给的是估计胜率（16 个固定估算种子，取整到 5%）。现在的 `stableSeed(seed, round, actor, gymId)` 全是公开量，客户端能精确算出结果；改成单打接力后顺序只有几种，公开种子会让预览退化成“试到赢为止”的查表。

**选择 1：对战格式**

| | **1A 单打接力（采用，2026-11-13）** | 1B 修正后的同场混战（未采用，2026-11-13） |
| --- | --- | --- |
| 规则 | 上面 | 保留混战，目标改为集火，加“首发吸引火力”（首发承受 50% 的攻击） |
| 顺序翻转结果（0.2 节，6 对 6） | 29.6% | 约 5.7% 加一点 |
| 宝可梦味 | 原作的形式：派谁先上、留谁压轴、属性互克一眼看懂 | 仍是“一堆数字互砍” |
| 回放 | 两只对站，天然适合像素对战画面 | 多对多，画面难读 |
| 成本 | 新文件，约 200 行；四种对战换接口 | 小 |

重标的依据（0.2 节的原型，同一批真实挑战）：

| 设置（同一批 427 次道馆挑战 / 886 次守卫挑战） | AI 胜 |
| --- | --- |
| v24 现状（混战，按实际带的人） | 道馆 375（87.8%） |
| 单打接力，按实际带的人，馆主 ×100% / ×80% | 348（81.5%）/ 391（91.6%） |
| **单打接力，同数，馆主 ×100%**：按原顺序取前 n 只 / 选最好的人和顺序 | 232（54.3%）/ 297（69.6%） |
| **单打接力，同数，馆主 ×80%**：按原顺序取前 n 只 / 选最好的人和顺序 | 319（74.7%）/ **384（89.9%）** |
| 守卫 v24（HP、攻、防 ×3–4） | 1 / 886 |
| 守卫：物种原值攻防、HP ×120% / ×150% / ×200%（同一批队伍，满 HP） | 712（80%）/ 666（75%）/ 396（45%） |
| 守卫 HP ×150%，按实际残血队伍 | 27（3%） |

- 道馆：同数规则下，馆主战力 ×80% 时 AI“选最好阵容”的胜率回到 v24 水平；**不选**（按原顺序取前 n 只）低 15 个百分点——这就是“决策的分量”。数值写成 `TEAM_BATTLE_RULES_V26.gymPowerPercent`（实现时用 216 局门槛再校一次）。
- 圣所守卫：物种原值攻防、HP ×150%（620 档）到 ×200%（860 档）时，同样的队伍满 HP 去打胜率 75% → 45%；配合 AI 只在估计 ≥ 50% 时挑战（也就是不再派残血队），守卫从“不可能”变成“要备战的 Boss”。
- 四天王：单打接力下对 1000 支“六只三阶、满 HP”随机队伍重新校到胜率约 60%（同 world-v24 §10 的做法）。
- 联盟大会：同样的队伍在单打接力里对 NPC 更强（0.2 节：对 NPC 胜率 混战 10.4% → 单打接力按报名顺序 13.5%、选好顺序 33.6%），NPC 战力 `npcBasePower` 要相应上调，目标是冠军赛结局份额相对 v25 锚点变化 ≤ 3 个百分点。

### 2.4 AI 选阵（`src/ai/battle-plan.ts`，只读视图）

- `chooseLineup(candidates, opponents, size, content)`：在 2 格内（大会、四天王为全部）有行动的宝可梦里，枚举人选和顺序（道馆最多 C(6,3) × 3! = 120 种），每种用 4 个固定估算种子（`stableSeed('ai-lineup', trial)`，不是权威种子）跑 `resolveTeamBattle`，取胜场最多、再取总损失 HP 最少、再按 id 排序的那个。每次评估 < 1 ms（单场约 30 回合整数运算）。
- 大会：6 只先按“历练 + 战力”取前 8 只，再枚举 8 选 6 的人选、对首发两位做全排列、其余按“对 NPC 名单平均倍率”排序；报名在赛前 5 轮（同 v24），赛前 1 轮按公布的 NPC 名单重排一次。
- 门槛：道馆在估计 ≥ 75%（4 局里赢 3 局）时挑战，取代“战力比 ≥ 1.25”；四天王 ≥ 50%（同 v24）；圣所 ≥ 50% 且每圣所每 3 轮最多一次。
- 训练：已有“预告期间训练克制劲敌属性 +20”的结构（`roster-plan.ts`），加一个来源：下一座道馆馆主属性的克制属性 +10。
- 只用视图；不产生被拒命令（核心测试：真实 AI 对局 0 次 `invalid-team` / `gym-unavailable`）。

### 2.5 表现：对阵卡与战斗回放（贴图、动画优先）

**战斗回放器**（新 `src/browser/battle-viewer.ts`，模态，Canvas）：

### 2.6 迷雾、权威、确定性

- 对战只用参战者自己的数据；道馆、四天王、大会、劲敌对决的事件与回放公开（v24 已公开），圣所守卫只给挑战者（同 v24）。
- 馆主队伍由公开设置算出（同 v24），对阵卡可以显示；大会 NPC 名单在赛前 5 轮写进视图（公开事件 `ChampionshipLineupAnnounced`）。
- 权威与预览共用 `resolveTeamBattle` 与 `teamBattleBlocker`；预览的估计胜率只用视图数据和固定估算种子，所以永远不会等于“预知”。
- v26 结算消耗 `state.rng`（每场 1 次）；v≤25 不变。全部整数；遍历按顺序数组与 id。
- **AI 对 AI 照样自动结算**：每场对战都在一条命令里结算完，没有回合中的交互；“换人”是公开的自动规则，“顺序”在命令里给出。所以 48 局冒烟与 216 局门槛的跑法不变。
- 回放记录：`BattleTraceV26 = { seed, format: 'relay', lineups: { home: string[]; away: string[] }, turns: { turn: number; acts: ({ kind: 'send' | 'switch' | 'faint'; side; id } | { kind: 'strike'; side; attackerId; defenderId; typeId; effectiveness; damage; roll; hpAfter })[] }[], winnerSide }`；v≤25 的 `BattleTrace` 结构不变，回放器按 `format` 分支。

### 2.7 平衡风险

| 风险 | 说明 | 对策 / 旋钮 |
| --- | --- | --- |
| 首枚徽章变晚 / 变早 | 同数规则让第 1、2 座道馆变成 1 对 1 | `gymPowerPercent` 按门槛校到首枚徽章中位与 v25 相差 ≤ 3 轮 |
| 冠军赛份额变化（23.1%） | 单打接力里玩家队伍对 NPC 更强 | `npcBasePower` 上调；验收 ±3 个百分点 |
| 起源胜利出现（现在 0） | 修好守卫后起源胜利从 0 变成可能 | 守卫 HP 倍率；目标起源份额 ≤ 8%；若最大单一方式超线先调它 |

| AI 选阵耗时 | 120 种 × 4 次 | 只在有挑战机会的回合算；道馆最多 3 选 n |

## 3. P3：可拦截、可对战的劲敌（`content.rivalDuels`）

### 3.1 规则

- **对决命令 `ChallengeRival { unitIds, stake }`**：本文明当前在场的劲敌全队（劲敌只针对你，不用指定）；**己方只数 = 在场劲敌只数**（同数规则，同道馆），都有行动、都在**任一**劲敌宝可梦 2 格内、至少 1 只与它相邻。每轮最多 1 次。对决用第 2 节的单打接力：劲敌的出场顺序固定（主克制在前），HP 用它们**在地图上的当前 HP**（你在地图上打掉的血算数），「劲敌气势」加到攻防上。
- **为什么同数**：单打接力里人多的一方几乎必胜（原型：第 1 次登场的劲敌 1 只，你派御三家 + 小拉达 2 只时任何气势下都是 100%）。同数之后决策才出现：劲敌带的是克制你御三家的物种，**御三家单挑几乎必输**（原型，气势 −12…0：小火龙对杰尼龟、杰尼龟对妙蛙种子 0%，妙蛙种子对小火龙 0–10%），而中性或克制它的宝可梦（小拉达、波波、凯西、喵喵……）在气势 ≤ −5 时 100% 赢——“别派搭档，派第二只”，正好接上捕捉。
- **登门挑战**：劲敌宝可梦到达目标城市旁时，城里和城旁 2 格内的己方宝可梦可以直接对决（“在城门口应战”），不需要出城追。
- **赌注 `stake`**（选择 3A）：

  | | 切磋 `spar` | 真剑 `serious` |
  | --- | --- | --- |
  | 赢 | 奖励 ×50%（四舍五入）；劲敌**不走**，本次还能再真剑对决 | 全额奖励 + “劲敌之证”（本次世代分再 +1）；劲敌全队离场（记为击退） |
  | 输 | 只写回 HP | 写回 HP；劲敌拿走“奖金” min(国库 × 20%, 30 × 第几次登场) 金币（原作输给训练家要付奖金）；本次剩余轮里劲敌气势 +3 |

- **奖励按局面放大**：劲敌这一方 HP 满时（你没在地图上先削血）金币 ×1.5（“堂堂正正”）；**连胜**：连续 2 次登场都击退劲敌后，下一次登场气势偏移再 +3、奖励 ×1.25（“劲敌也在变强”）。基础表沿用 v24（25 金 + 2 球 / 50 金 + 20 科研 / 80 金 + 50 经验，世代分 1 / 2 / 3）。
- **地图战斗照旧**：可以继续在地图上一只只打（v24），对决只是另一条路。劲敌 HP 在两者之间共享。
- **第 4 次登场：联盟大会**（后期钩子）：第 100 轮以后的第一届大会，劲敌占一个 NPC 名额（6 只，主克制三阶 + 副克制三阶 + 本地区 4 只三阶，战力 = 该届 NPC 战力 + 60），赛前 5 轮在名单里公布。在任何一场淘汰他：世代分 +2、金币 100、台词卡“宿命的对决”。别的文明遇到他只是普通 NPC。
- **在场轮数**沿用 v25（6 / 7 / 9）；对决不改变劲敌的推进和打城规则。

### 3.3 AI（`src/ai/rival-plan.ts`）

- v24 的应对小队照旧挑人；小队里有单位满足对决条件时，用 `chooseLineup` 估计对决胜率：≥ 60% 发真剑；35–60% 且劲敌离目标城 ≤ 2 格时发切磋（拖住它、拿一半奖励）；否则照旧地图战斗。

## 7. C：《文明》式单位操作

### 7.1 多回合前往（选择 6A：客户端路标）

- 右键 / 长按远处的格子：显示路线（虚线，每回合终点画 ①②③ 回合数），确认后设路标。路线用玩家**已知地形**做 Dijkstra（未探索格按草原花费估），与 `reachablePaths` 同一套通行规则。
- 存在客户端（`localStorage`，键 = 对局 id + 玩家 + 单位 id）。**每当轮到你**（视图 `activePlayerId === playerId`）、单位有行动时，客户端在你操作之前为每个有路标的单位发一条普通 `Move`（到这回合能走到的、路线上最远的格），动画照常播放。

### 7.2 平民与宝可梦同格（`content.stacking`，选择 7A）

- **叠放**：一格最多 **1 只宝可梦 + 1 个职能单位**（开拓队、工匠、商队），必须同一主人。两只宝可梦、两个职能单位不能同格。
- **通行**：可以穿过任何己方单位；只能停在“同一层”空着的格子上。城市格不变（城里不受叠放限制的现状保留）。
- **攻击与捕获**：攻击叠放格时，目标是宝可梦；职能单位在有己方宝可梦同格时**不能被选为目标**（捕捉只对野生宝可梦，职能单位本来就不能被捕获；本稿不引入《文明》的“俘获平民”）。宝可梦被击倒（去休养）后，职能单位留在原格，之后可以被攻击（同现在）。会出手的野生宝可梦轮末只打同格里的宝可梦。劲敌不打职能单位（不变）。
- **建城**：开拓队与护送宝可梦同格时可以建城；宝可梦留在新城里。
- **出生**：新单位可以出生在“另一层”空着的格子上（与 v25 的出生避让一起，减少“刚训练的小火龙堵死唯一通路”）。
- **控制区**：职能单位不产生控制区；与宝可梦同格时按宝可梦算。
- **AI**（`src/ai/plan.ts`，只在 v26）：开拓队出城时，最近的一只空闲宝可梦（不在城防、不在战线）被指派为**护送**，与开拓队同格移动直到建城；v24 的“职能单位不走到会出手的野生旁边”对有护送的开拓队放宽为“不走进 2 只以上会出手的野生旁边”。
- **迷雾**：同格的两个单位都是可见实物，看得见格子就看得见两者；视图结构不变（`units` 里本来就是列表），渲染把职能单位画成格子右下角的小徽记。
- **平衡**：门槛诊断里“开拓队反复被野生打倒”是第三城晚的主因之一（`gate-v24-ai.md` 85d7d2b）。护送预计让第三城提前（目标 ≤ 22，现在 24）；风险是 AI 扩张更快、信仰门槛更早满足（第 5.5 节）。旋钮：护送只在开局（< 4 城）启用。

**选择 7**：**7A 1 + 1 叠放（采用，2026-11-13）**；7B 只允许穿过己方单位、出生避让，不叠放（未采用，2026-11-13：改动小，但开拓队仍无法被保护）。
