# B4：第三轮平衡迭代方案

> 本文只设计下一轮实验，不修改 GDD、正式数值或 AI/core。共同研究底座是 I1；J1–J6 的效果均为待模拟验证的假设，不是实测结论。轮上限保持 100，征服目标保持 ≥40%。

## 1. 输入、复算与限制

输入为同一 100 种子、300 局的 I1–I6 逐局数据，原始目录在共享报告区 `reports/sim/m5-6-i1` … `m5-6-i6`。汇总证据为共享报告 `sim-balance-b3.md` 与 `reports/sim/m5-6-proof/comparison.json`。

| 方案 | 征服 | 平均终局 | 1v3 终局 | 先手 | 好战对扩张 | 好战对保守 | 保守对扩张 |
|---|---:|---:|---:|---:|---:|---:|---:|
| I1 | 82/300 = 27.33% | 89.15 | 95.33 | 54.00% | 45.45% | 47.06% | 12.12% |
| I2 | 76/300 = 25.33% | 91.12 | 96.39 | 51.50% | 56.06% | 70.59% | 12.12% |
| I3 | 76/300 = 25.33% | 91.12 | 96.39 | 51.50% | 56.06% | 70.59% | 12.12% |
| I4 | 76/300 = 25.33% | 91.13 | 96.39 | 52.50% | 56.06% | 69.12% | 13.64% |
| I5 | 75/300 = 25.00% | 91.12 | 96.39 | 52.00% | 56.06% | 69.12% | 12.12% |
| I6 | 75/300 = 25.00% | 91.13 | 96.39 | 53.00% | 56.06% | 67.65% | 13.64% |

配对列依次表示好战型胜扩张、好战型胜保守、保守型胜扩张。I1 的两组好战配对已在 40–60%，但征服、1v3 和保守对扩张不达标，不能称为平衡通过。

B3 的可分离证据：

- I1−B 撤回好战经济放行，征服 −4.33 个百分点，好战对扩张 −22.73、对保守 −26.47 个百分点；经济门槛是失衡放大因素。
- B−I3 只放宽攻城 4→3 兵，征服 +6.33 个百分点，好战攻城席位 161→193，HQ 占领 171→213。
- I4−I3 只加快保守开拓，保守城市均值 +0.15，但科技不变，保守对扩张只 +1.52 个百分点。
- I5−I3 只放宽保守反攻，保守对扩张不变；I6 相对 I4 的该配对也逐字节不变。
- I2/I3 有 297/300 逐局文件一致，3 局出现宣战分歧，300 局胜负与终局轮数相同、299 局完整 outcome 相同。因此只能说 **1250–1500 在本样本未改变胜负和终局轮数**，不能扩大成“任何过程或所有对局都没有作用”。

固定 100 种子是探索样本，不是发布置信结论。第三轮仍以同种子做因子差分，最终候选必须按 D18 使用独立新种子。

## 2. 第三轮要解决的机制

### 2.1 征服缺口与保守路线

I1 要从未经追加样本的 82/300 达到 120/300，需净增 38 局征服、+12.67 个百分点。保守对扩张只有 8/66 胜，且 66 局全部计分、0 局征服；至少要到 27/66 才超过 40%。

D41 已批准保守型有限主动宣战。J1/J2 因而只改变保守宣战门槛，不再用开拓间隔、反攻倍率或通用城市分重复测试已经失败的路线。`conservativeDeclareStrength` 只控制主动宣战；现有 `conservativeStrength=2000` 仍控制攻城，避免 J2 把 1.5 倍同时扩散到两个判断。

### 2.2 1v3 的断点在首夺 HQ 之后

分析脚本 `/tmp/balance_m5_iter3_analysis.mjs` 重放 I1 的 100 个 1v3，完整输出为 `/tmp/balance_m5_iter3_analysis.json` 与 `.stdout.json`。结果：

| 指标 | 结果 |
|---|---:|
| 征服 / 计分终局 | 23 / 77 局 |
| 征服局平均 / 中位终局 | 79.70 / 80 轮 |
| 计分局终局 | 77 局全部 100 轮 |
| 好战型至少首夺一个 HQ | 71 席 |
| 其中最终征服 | 23 席，32.39% |
| 首夺 HQ 中位：最终征服 / 未征服 | 36 / 37.5 轮 |
| 夺下第二 / 第三个 HQ 的好战席位 | 49 / 22 席 |
| 第一→第二 HQ 间隔中位 | 19 轮 |
| 第二→第三 HQ 间隔中位 | 19.5 轮 |
| 首夺后城市攻击中位：最终征服 / 未征服 | 49 / 20.5 次 |
| 首夺后敌 HQ 攻击中位：最终征服 / 未征服 | 30 / 9.5 次 |

首夺时点在两组间接近，而后续攻击量和 HQ 转化差距很大，所以“再提前第一次攻城”不是唯一解释。48 个未征服的好战首夺席位中，19 个之后没有攻击另一个敌 HQ；数值杠杆不能替这 19 席创建目标，目标连续性属于另一个 AI 行为问题。

首夺后的中立城市攻击只占 12.71%，不支持“主要时间都用于清理中立城市”。全 100 局只有 8 局发生同城重复占领，共 14 座城、26 次重复占领，因此占城后 HP 是低优先级保持战果杠杆，不应预期它单独补上 12.67 个百分点。

第三轮用城市 HP 和攻城倍率缩短每次交战，用占城后 HP 测试重复占领损耗，同时保留上述目标连续性诊断。不得把组合提升全部归因于城市数值。

## 3. 共同底座与新增字段合同

六个补丁都显式保留 I1：

```json
{
  "balance": {
    "city": { "baseHp": 80 },
    "score": { "cities": 80 }
  },
  "ai": {
    "aggressiveSettlerCities": 3,
    "aggressiveSiegeUnits": 3,
    "aggressiveWarStrength": 1250
  }
}
```

未写字段保持默认，包括保守攻城 `conservativeStrength=2000`、保守开拓间隔 15 和好战接壤距离 5。本轮不改物种，因此没有新的 B2 物种消融或 D15 数值变化；若后续加入物种补丁，必须逐条按 B2 重做阶段预算、成本和全对全 D15。

实验字段暂名：

- `conservativeMayDeclareWar`：布尔；D41 总开关，正式默认先保持 false 以复现旧批次。
- `conservativeDeclareStrength`：千分比；已观察对方战斗单位数 ×该值/1000 ≤ 己方已观察战斗单位数时才允许主动宣战。
- `conservativeBorderDistance`：格数；沿用好战型的观察口径，已观察对方城市距己方单位不超过该值即为接壤。J1/J2 固定为 1，不混测距离。
- `balance.city.capturedHp`：攻击占城后的 HP。J5/J6 暂用 60；只替代当前占城恢复 50，HQ 淘汰导致的余城中立化仍恢复 50。实验值不得超过该城最大 HP。

coder 可对齐实际字段名，但 manifest 必须记录最终字段与补丁哈希。若字段尚未实现，不得删除字段后运行并冒充 J1/J2/J5/J6。

## 4. 第三轮因子补丁

机器可读补丁为 `/tmp/balance_m5_iter3_patches.json`，校验为 `/tmp/balance_m5_iter3_patch_validation.json`。当前 J3/J4 完整 `parsePatch` 通过；J1/J2 缺 D41 字段，J5/J6 缺 `capturedHp`，失败符合预期。剥离新字段后的其余配置六组全部通过。完整补丁 canonical SHA-256 分别为：J1 `9fc5ff07…45c`、J2 `32634376…424`、J3 `e73ba55b…238`、J4 `e3e666ca…4c0`、J5 `2080c3b7…e7`、J6 `a045bf8d…c6a`。

### J1：D41 默认门槛

假设：2 倍军力且接壤能开放保守对扩张的征服路线，同时避免保守过早宣战。

```json
{
  "balance": { "city": { "baseHp": 80 }, "score": { "cities": 80 } },
  "ai": {
    "aggressiveSettlerCities": 3,
    "aggressiveSiegeUnits": 3,
    "aggressiveWarStrength": 1250,
    "conservativeMayDeclareWar": true,
    "conservativeDeclareStrength": 2000,
    "conservativeBorderDistance": 1
  }
}
```

对比：J1−I1 只测 D41 在 2000/1 格的增量。

### J2：D41 低门槛敏感性

假设：若 J1 宣战触发太少，1500 可增加宣战与攻城机会；若好战对保守或滚雪球恶化，则不能为了保守对扩张而接受。

```json
{
  "balance": { "city": { "baseHp": 80 }, "score": { "cities": 80 } },
  "ai": {
    "aggressiveSettlerCities": 3,
    "aggressiveSiegeUnits": 3,
    "aggressiveWarStrength": 1250,
    "conservativeMayDeclareWar": true,
    "conservativeDeclareStrength": 1500,
    "conservativeBorderDistance": 1
  }
}
```

对比：J2−J1 只差主动宣战军力比 2000→1500；攻城仍为 2000。1500 只是实验敏感性，不是 D41 已批准的正式文字。

### J3：城市基础 HP 60

假设：降低所有城市的基础耐久可缩短 HQ 攻击段、增加征服并提前 1v3 终局；必须检查是否让好战重新过强。

```json
{
  "balance": { "city": { "baseHp": 60 }, "score": { "cities": 80 } },
  "ai": {
    "aggressiveSettlerCities": 3,
    "aggressiveSiegeUnits": 3,
    "aggressiveWarStrength": 1250
  }
}
```

对比：J3−I1 只差基础 HP 80→60；不含 D41 或其他城市因素。

### J4：投石改装攻城倍率 1750

假设：只提高已研究投石改装的攻城定位对城伤害，可缩短后期连续攻城，而不普遍提高所有兵种或前期伤害。

```json
{
  "balance": {
    "city": { "baseHp": 80 },
    "effects": { "siegeMultiplier": 1750 },
    "score": { "cities": 80 }
  },
  "ai": {
    "aggressiveSettlerCities": 3,
    "aggressiveSiegeUnits": 3,
    "aggressiveWarStrength": 1250
  }
}
```

对比：J4−I1 只差攻城倍率 1500→1750。按科技解锁和攻城定位分别报告攻击段，不能把效果归因于全部单位。该字段不影响宝可梦对宝可梦伤害，不触发新的 D15 上限。

### J5：占城后 HP 60

假设：占城恢复 50→60 可减少重复占领和回防，保留推进成果；样本只有 8 局出现重复占领，所以这是低优先级假设，并需防止滚雪球上升。

```json
{
  "balance": { "city": { "baseHp": 80, "capturedHp": 60 }, "score": { "cities": 80 } },
  "ai": {
    "aggressiveSettlerCities": 3,
    "aggressiveSiegeUnits": 3,
    "aggressiveWarStrength": 1250
  }
}
```

对比：J5−I1 只差占城后 HP；基础 HP 和中立化 HP 不变。

### J6：D41 默认门槛 + 三个征服杠杆

假设：若 J1/J3/J4/J5 各自有效但单独不足，组合才可能同时满足三组目标。它不是新的单因子证据。

```json
{
  "balance": {
    "city": { "baseHp": 60, "capturedHp": 60 },
    "effects": { "siegeMultiplier": 1750 },
    "score": { "cities": 80 }
  },
  "ai": {
    "aggressiveSettlerCities": 3,
    "aggressiveSiegeUnits": 3,
    "aggressiveWarStrength": 1250,
    "conservativeMayDeclareWar": true,
    "conservativeDeclareStrength": 2000,
    "conservativeBorderDistance": 1
  }
}
```

对比：J6 与 J1+J3+J4+J5 的字段完全对应。总交互残差用 `J6 − J1 − J3 − J4 − J5 + 3×I1`；它只表示四项合并未被主效应解释的部分，不能继续拆成某两项的交互。若 J2 优于 J1，不能在缺少 J2 组合组时声称 J6 已证明 1500 的组合效果。

## 5. 运行、诊断与胜者选择

1. 先等新字段实现并让六份完整补丁全部通过 `parsePatch`；任一失败就暂停该组并报告，不运行剥离字段版。新代码默认关闭 D41 后，I1 应与现有 I1 的 300 局逐字节一致；否则停止跨版本差分并先定位默认行为变化。
2. 六组都跑同一 100 种子、300 局，保留 manifest、patch SHA 和逐局数据；同 patch 双跑确认确定性。逐批报告 defect、aborted、迷雾拒绝和提前终局。
3. 除 B3 全部指标外，必须增加：
   - 保守主动宣战的满足门槛次数、实际宣战次数、首次宣战/攻城/HQ、对扩张的征服局数；分别列主动与被动战争。
   - 1v3 首夺 HQ 后的第二/第三 HQ 转化与间隔、后续敌 HQ 攻击、无后续 HQ 目标席位、重复占领次数。
   - J4 的投石科技解锁后攻城攻击段；J5 的同城重复占领与回防攻击。
4. 同批双跑只证明确定性，不证明平衡。阈值附近按 D18 追加相关新种子；最终发布候选另跑独立新样本。

**沿用 B3 §4 的选择顺序，补充 D41 平局规则：**

1. 硬排除：defect 非 0、aborted >5%，或先手 >55%、滚雪球 >75%、捕捉离开 3–10、无属性优势击坠 ≤25%、平均/1v3 轮数越界者排除。
2. 全部原目标达标者优先；其中选三组配对离 40–60 最大距离最小者，再选滚雪球更低者。
3. 若没有全达标：依次按三组配对达标组数降序、征服率降序、三组配对到区间的最大距离升序、滚雪球升序。不得只按征服最高选胜者。
4. J1/J2 都能接受时优先 2000，因为它符合 D41 草案且行为变化更保守；1500 单独胜出只成为研究候选，正式采用需用户追加决定。
5. 好战已达标的两组若因城市杠杆离开 40–60%，不得用“保守变强”抵消；保留 I1 好战设置，回退城市杠杆或继续单因子迭代。
6. 没有候选满足要求时只输出“下一轮实验胜者”，不能写“平衡通过”。

## 6. GDD v0.7 §3.14 文字草案（不写入 mvp-gdd.md）

为保证主动宣战后确实有攻城路线，宣战与攻城两个单元格需要作为同一项 D41 修改：

| 维度 | 保守型新文字草案 |
|---|---|
| 宣战时机 | 与目标接壤（已观察的对方城市距己方单位 ≤1 格）且已观察的对方战斗单位数 ×2 ≤ 己方时，可以主动宣战；被宣战后正常作战 |
| 攻城时机 | 与目标处于战争且已观察军力 ≥ 对方 2× 时攻城；主动宣战仍须满足宣战时机条件 |

军力继续使用 §3.14 的已观察信息，休养单位不计入战斗单位数；不读取隐藏状态。默认字段先关闭只是为了旧实验复现，不改变这份拟议玩法文字。J2 的 1.5 倍不写入草案。

## 7. 超出当前授权或需另行决定

1. **正式采用 1500 主动宣战门槛**：D41 文字是 2 倍；J2 仅获准实验。
2. **首夺 HQ 后的目标切换/持续推进 AI**：19/48 个未征服席位没有再攻击另一个 HQ。若 J3–J6 仍无法清场，需要新增目标优先级或连续性规则；这不是现有数值字段，需另行设计和授权。
3. **占城后 HP 新规则落地**：本轮可提实验字段，但正式修改 core 默认值及 GDD 仍留到 v0.7 用户确认；不得借实验直接改正式行为。
4. **保守捕捉范围、性格专属计分、物种补丁**：本轮均不采用。它们不能替代 D41 验证；以后若启用，分别需要对应规则决定，物种还需逐条 B2/D15 消融。
5. 本方案不要求也不允许直接修改 `mvp-gdd.md`、AI/core 或正式默认值。
