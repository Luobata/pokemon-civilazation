# 文明扩展：供奉、圣所、幻影、起源与联盟大会（S23–S28）

- 版本：v1（2026-11-01）
- 规则包：`civilization-v1`；只在 `GameSetup.expansionVersion === 1` 时初始化。
- 代码边界：核心逻辑在 `src/core/civilization-systems.ts`，数值与内容在 `src/content/civilization-systems.ts`。默认旧版 `GameState` 不创建 `state.expansion.civilization`，因此旧版存档、回放和 UI 行为保持不变。
- 数值状态：本文列出可复算规则；尚未把这些数值声明为长局平衡结论。

## 1. 状态与公开接口

扩展状态挂在 `state.expansion.civilization`，保存：

- 每名玩家的供奉点、累计供奉、本回合各城市供奉、幻影费用、已召唤/待激活/名人堂幻影与名字账本。
- 四个唯一圣所的位置、所有权、守卫状态和挑战回合。
- 石板拥有者、待结算工程师生产加成、联盟大会日历与报名。
- 每对文明的外交协议、提案回合、拒绝冷却、信任与背叛记录。
- 已达成的 `origin` 或 `championship` 胜利。

核心接口是：

```ts
initializeCivilization(state, content): CivilizationState
validateCivilizationAction(state, actorId, action, content): string | null
applyCivilizationAction(state, actorId, action, content): EventPayload[]
resolveCivilizationRound(state, content): EventPayload[]
observeCivilization(state, playerId, visibleTileIds, content?): CivilizationView
consumeCivilizationProduction(state, cityId): number
checkCivilizationVictory(state, content): EventPayload[]
isCivilizationAction(value): boolean
planCivilizationAction(view, content): CivilizationAction | null
```

`consumeCivilizationProduction` 必须在该城市常规经济生产结算前调用一次；它把工程师幻影的待结算加成写入队首订单并清空待结算值。`checkCivilizationVictory` 使用共享 `finishGame(state, 'origin' | 'championship', [winner], content.world)`，常规行动和轮末结算在条件成立时会调用它。

观察函数只返回：

- 可见圣所和这些圣所可见的石板拥有者；
- 观察者自己的供奉、幻影、外交与报名详情；
- 公开的大会历史、冠军数、下一届日程；
- 观察者自己的规划摘要。

所有嵌套观察值都是深拷贝，修改视图不会回写权威状态。外交关系先按观察者过滤，因此不会把第三方之间的私有协议泄露给观察者。

## 2. S23 供奉与幻影

供奉按城市执行：

- `10 food → 5 offering points`；
- `20 gold → 5 offering points`；
- 只有已经控制至少一座圣所的文明才能供奉；
- 每城每回合至多一次，任意资源都占用该城本回合供奉机会；
- 轮末清空 `offeredThisRoundByCity`。

幻影五类各只能召唤并激活一次：

| 类别 | 召唤 | 一次性效果 |
|---|---|---|
| 科学家 | 供奉点 | 当前研究 +40，溢出进入研究储备并可完成科技 |
| 工程师 | 供奉点 | 指定己方城市下一次生产结算 +40 |
| 商人 | 供奉点 | +60 金币 |
| 将军 | 供奉点 | 1–6 只己方宝可梦各 +20 XP |
| 大艺术家 | 供奉点 | 指定己方城市 +40 食物 |

第 n 次召唤的费用是 `30 + 15 × n`，其中 n 从 0 开始。类别 ID 是稳定存档键；召唤时从该类别未使用的名字池中按 `seed + playerId + category` 的稳定哈希选名。名字只影响叙事和事件，不影响数值。

工程师效果先记录在 `pendingProductionByCity`，不直接改队列；这保证效果发生在下一次生产结算前，并且由集成管线显式消费。商人、将军与大艺术家立即生效。激活后类别进入名人堂，不能再次召唤或激活。

## 3. S24 传说圣所与守卫挑战

初始化时在地图四个象限各选一个唯一非海洋、非城市格。选择按到象限锚点距离、离边缘更远、行优先索引排序，不消耗共享游戏 RNG。四个圣所和石板为：

| 圣所 | 石板 | 守卫物种 | 挑战强度 |
|---|---|---|---:|
| 湖畔圣所 | 湖泊石板 | 乘龙 | 620 |
| 天空圣所 | 天空石板 | 快龙 | 700 |
| 灵界圣所 | 灵界石板 | 耿鬼 | 780 |
| 斗技圣所 | 斗技石板 | 怪力 | 860 |

建立圣所消耗 `80` 金币，必须由位于圣所格的己方部署单位执行。建立只取得圣所所有权，不直接取得石板。

守卫挑战条件：

- 圣所属于行动者；
- 石板未被取得；
- 该玩家本回合未挑战过此守卫；
- 使用 1–3 只己方、已部署、有行动点的宝可梦；
- 全部队距圣所不超过 2，且至少一只正位于圣所格。

挑战使用实际战斗，而不是总强度比较。守卫属性按 `挑战强度 / (HP + 攻击 + 防御)` 缩放。双方使用真实 HP、攻击、防御、威力、主副属性、扩展双属性克制、地形乘区和 85–100 稳定随机数。随机流来自地图种子、回合、玩家、圣所和固定盐，不消耗大地图 RNG，也不改变其他行动。

战斗逐轮执行：双方按攻击降序、稳定 ID 升序出手，攻击者选择预计每 HP 伤害最高的目标。事件保留每轮攻击、伤害、克制、随机数与目标剩余 HP 的完整 trace。挑战后所有本地参赛宝可梦消耗行动点；存活单位回写实际 wear HP，但至少保留 1 HP，便于地图单位继续存在并可进入既有恢复体系。

挑战胜利才取得该圣所石板；失败只记录冷却与 wear，需要下一回合再挑战。

## 4. S25/S26 起源胜利

玩家必须通过四个守卫挑战分别取得四块石板。第四块石板到手时写入：

```text
civilization.victory = { kind: 'origin', playerId, round, tablets }
```

随后立即调用共享胜利结束逻辑，游戏结局为 `origin`，唯一胜者为该玩家。部分石板不会因为其他玩家胜利而删除；圣所本身全图唯一。

## 5. S27 联盟大会与冠军胜利

第一届在初始化后第 40 轮举办，之后每 20 轮一届。报名条件：

- 恰好 6 只己方宝可梦；
- 报名者仍拥有这些单位；
- 与所有存活文明处于和平；
- 同届可更新报名，本届结算后清空。

报名时记录稳定种子强度：`物种 max HP + 攻击 + 防御 + floor(XP / 10)`。NPC 按需补足到 6 名参赛者；每支 NPC 队伍同样有 6 只从实际规则内容物种表稳定选择的宝可梦，目标总强度随届数提高，并保留个体物种差异。

六名参赛者按报名强度排序，前两名轮空。实际 bracket 固定：

1. 初赛一：3 号种子 vs 6 号种子；
2. 初赛二：4 号种子 vs 5 号种子；
3. 半决赛一：1 号种子 vs 初赛二胜者；
4. 半决赛二：2 号种子 vs 初赛一胜者；
5. 决赛。

每场都是 6v6 逐轮战斗，使用与守卫挑战相同的双属性克制、伤害、地形与稳定随机流；队内 HP wear 跨场比赛延续。每场比赛记录双方阵容、每轮攻击 trace、伤害、随机数与比分。种子只决定赛程和轮空，不直接决定胜者。

玩家单位在大会结算后回写至少 1 HP 的实际 wear，并消耗行动点。NPC 不进入地图、不拥有城市、不计入胜利。冠军获得一届头衔；第二名头衔立即写入 `championship` 胜利并以该玩家为唯一胜者结束游戏。历史、冠军数与完整 bracket trace 公开可见。

## 6. S28 深度外交

扩展外交叠加在既有和平/战争状态上，不替换旧外交。提案和协议只在双方存活且基础关系为和平时有效。

- 结盟与贸易都必须先提案、后由对方接受；
- 提案 5 轮未回应即过期；
- 拒绝或已发出提案后，同一协议 10 轮内不得重复提案；
- 主动解除联盟只结束联盟；
- 背叛仅可在活跃联盟上执行。

贸易成立后，每 5 轮给双方各 `+4` 金币，并把共同信任 `+1`，信任上限 100。背叛消耗背叛者 `20` 金币，结束联盟和贸易，把信任设为 `-50`，施加 10 轮结盟冷却，并在该关系账本中永久记录背叛者。基础战争爆发时，联盟、贸易与相关提案自动结束。

`planCivilizationAction` 是观察驱动的确定性 AI 辅助，不读取隐藏状态。其优先级是：站在可见空圣所上的可负担建立、仍有幻影需求时的可负担供奉、可召唤/激活幻影、响应和平且存活对手的可信提案、已建立圣所的可行守卫挑战、临近大会报名、可信结盟与贸易。供奉需要已控制圣所；金币供奉会保留 100 金，五类幻影都用完后再继续供奉没有收益。规划关系带公开基础和平状态与对手存活状态，提案与响应完全镜像验证条件及冷却，避免向交战或已淘汰文明发起外交。

## 7. 事件、迁移与测试口径

新增事件按可见性区分：

- 私有经济、幻影、生产与 wear 事件带 `playerId`；
- 公开大会、已成立协议的变更与胜利事件带 `public: true`；
- 结盟与贸易的提案、拒绝、提案过期只投影给协议双方，第三方不能从事件获知私下谈判结果；
- 大会与守卫事件包含完整稳定 trace，供调试和回放审计。

模块状态带 `version: 1`；没有旧版本迁移负担。直接核心测试覆盖：

- 供奉成本、每城限一次和轮末重置；
- 五类幻影递增费用、全部一次性效果与名字账本；
- 圣所建立、本地队伍约束、实际战斗 trace、行动点与 HP wear；
- 四块石板与 origin 胜利；
- 大会 NPC 补足、6v6 roster、五场 bracket、跨届日历与第二冠胜利；
- 联盟/贸易互相同意、贸易 cadence、背叛惩罚与战争自动解散；
- 观察隐藏、关系过滤与深拷贝隔离；
- 动作 guard 与规划器不重复供奉。

全局长局平衡仍需由根集成后的批量 AI 对局完成；本文不将规则可复算等同于胜率已调平。
